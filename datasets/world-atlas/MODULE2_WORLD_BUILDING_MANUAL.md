## 第一部分：核心认知（严禁混淆的四层边界）

### 1.1 强认知母体二创型连续男频的双母体分权

不要把世界资料混成一锅“背景百科”。必须严格区分四层：

| 层级 | 中文名 | 回答的核心问题 | 归属与真值边界 |
| :--- | :--- | :--- | :--- |
| **L1** | **原生母体世界**（Objective Source World / World Atlas） | **客观上 / 原作上 / 史实上，本来是什么？**（全时间线人物、关系、组织、制度、权力规则、资源价格、事件因果） | 模块二只读公共参考层（`source_worlds`）；**绝不因某本小说开书时间而删减后期人物与事件，绝不写穿越主角** |
| **L2** | **认知母体世界**（Cognitive Mother） | **目标男性读者在打开书之前，脑子里默认以为它是什么、默认期待什么？**（影视/动漫/通俗历史/同人圈共同沉淀的刻板印象、公共情绪资产、自带价格的人物/名场面/流派惯性） | 模块二公共认知参考层（以 `kind:"information"` 的 `information:cognitive-*` 卡片挂入同一世界库，与原生母体事实严格分卡，**绝不用刻板印象覆盖原生事实**） |
| **L3** | **认知钩子**（Cognitive Hooks，2026-09-03 分权） | **轻轻一碰读者脑中就会“自动播放”，且拿出来写男频用得上的具体高价资产是什么？**（如写轮眼、飞雷神、尸体摸尸能力容器、血继融合零件、木叶F4、晓红云袍） | Reader-side 记忆入口与可开发资产；在认知母体卡中标明其“为何响、能怎么二创用”，具体带电度与 Reader Price 留到项目调用期判断 |
| **L4** | **派生世界 / 项目现实**（Project Reality） | **本书男主伸手改变之后，实际发生了什么？** | 单本小说的 Canon / Timeline / Knowledge；**绝不写回模块二公共母体库** |

### 1.2 为什么要把「原生母体」和「认知母体」严格分开？
因为二创最便宜、最强的两大阅读张力就来自它们的**差值**：
- **横向差值（认知母体 vs 原生母体）**：「读者和普通角色以为它是这样（刻板印象），但底层真实规则/利益/人性其实是那样（原生母体真相）」→ 天然长出信息差、误判、套利空间与“重新认识”的快感。
- **纵向差值（原著/历史原本轨迹 vs 男主改写后的派生现实）**：「原著本来会这样死/这样败，但男主靠自身欲望、根心和现实杠杆把它改写了」→ 产生“重新改变”的爽感。

### 1.3 八条防重犯铁律（来自 `docs/mmorpg/10`、`12`、`13`、`15`）
1. **严格一对象一卡（原子粒度）**：严禁多合一打包卡（❌「漩涡帮、虎爪帮与瓦伦蒂诺」「三忍」「晓组织全员」；✅「漩涡鸣人」「自来也」「大蛇丸」「纲手」「宇智波鼬」各自独立成卡）。
2. **People-Centered 第一原则**：代码检索优先级第一名是 `character`。**具名人物卡必须占单世界总卡数的 35%～50%**；组织必须链到掌权者、地点必须装入常驻人物与入口把关人、资产/能力必须链到持有人/传授者/争夺者（权力必须有“人形接口”）。
3. **保留全时间轴，绝不按开书时期删资料**：例如火影必须同时收录战国/建村、二战、三战、九尾之夜、中忍考试、佩恩、四战全期人物与事件；同一人物/组织跨时期的状态变化在正文中按时间分段写清。
4. **严禁自动编造能力限制与弱点**：原作/史料没写清楚的限制、反制、代价必须写明“原作未明确/未知”，**绝不为了游戏平衡强行给能力或金手指编造削弱代价**。
5. **人物价值独立于男主**：写清角色/组织/资产在原世界本来拥有的目标、权力、地位、社会评价与稀缺性，**绝不用“男主能否收服/已取得”的视角写母体卡**。
6. **女性人物保持真实高价**：写清女性角色自身真实的性格、立场、社会地位、人脉、能力、魅力与选择权（高价的真实人格让她的选择和关系变化值钱），既不弱化为纸片人，也不改写成脱离原著的大女主叙事。
7. **100% 遵守代码官方 `##` 分节与标准反向关系词**：否则 UI 反向关系图与 LLM 上下文抓取会失效。
8. **物理存储不新增表**：全部通过 `datasets/world-atlas/<worldId>/world.json` + `batch-*.json` 落盘，用 `scripts/import-world-atlas.ts` 幂等导入本地 SQLite（`source_worlds` + `source_records` + `source_world_lore_sections` + `source_relations`）。

## 第二部分：代码级硬格式标准（直接对齐 `world-atlas.ts`）

### 2.1 `world.json` 规范（严格校验 SQLite CHECK 约束）
```json
{
  "id": "naruto",
  "name": "火影忍者（完整母体世界）",
  "kind": "fictional",
  "description": "《火影忍者》完整时间轴双母体资料库：涵盖原生母体全期人物/组织/地点/制度/能力/资源/事件原子卡，以及独立分层的读者认知母体与横向差值卡。"
}
```
> ⚠️ `world.json` 的 `kind` **只能**是以下 4 个值之一：`fictional` | `historical` | `era` | `original_reference`。

### 2.2 `batch-XX.json` 卡片对象规范
每个批次文件为合法 JSON 数组（建议每批 **10～15 张**，防止模型截断），单卡结构：
```json
{
  "entityKey": "<kind>:<english-kebab-id>",
  "kind": "character",
  "name": "旗木卡卡西",
  "aliases": ["拷贝忍者", "写轮眼卡卡西", "六代目火影"],
  "content": "# 旗木卡卡西\n\n## 身份与人生\n...\n\n## 关系索引\n所属组织：[[木叶隐村]]\n老师：[[波风水门]]\n学生：[[漩涡鸣人]]、[[宇智波佐助]]、[[春野樱]]\n拥有：[[写轮眼]]\n掌握：[[雷切]]\n参与：[[神无毗桥之战]]"
}
```

### 2.3 17 种合法 `kind` 与代码官方 `##` 分节模板（全量速查）
每张卡正文 **380～600 字**（核心人物与认知母体卡可到 500～700 字），必须使用下表对应 `kind` 的官方 `##` 分节，并在末尾附加 `## 关系索引`：

1. **`character`（人物 · 第一优先级）**：
   `## 身份与人生` / `## 所在与组织` / `## 人物关系` / `## 力量与资源` / `## 性格与行动方式` / `## 重要经历` / `## 社会评价与私人生活`
2. **`organization`（组织/家族/派系）**：
   `## 组织形态与区域` / `## 领导与成员` / `## 资产与资源` / `## 决策与权限` / `## 当前目标与事务` / `## 对外关系`
3. **`position`（职位/身份位）**：
   `## 职位性质` / `## 任命/取得方式` / `## 实际权限` / `## 限制与监督` / `## 历任/现任` / `## 相关组织`
4. **`population`（人口/职业群体）**：
   `## 分布与生计` / `## 职业与组织` / `## 资源与需求` / `## 社会关系` / `## 当前变化`
5. **`location`（地点/区域/场域）**：
   `## 范围与地理` / `## 交通与通路` / `## 组织与人物` / `## 资源与活动` / `## 准入与控制` / `## 日常运行` / `## 相邻世界内容`
6. **`resource`（资源）**：
   `## 分布与产地` / `## 控制者` / `## 价值` / `## 取得方式` / `## 加工与流通` / `## 用途` / `## 再生/耗尽与替代`
7. **`item`（物品/资产/忍具/法宝）**：
   `## 本体与权属` / `## 来源` / `## 用途` / `## 取得/转让` / `## 限制` / `## 当前持有人` / `## 相关事件`
8. **`ability`（能力/技能/忍术/功法）**：
   `## 能力本体` / `## 取得与学习` / `## 实际动作` / `## 作用范围` / `## 前置与反制` / `## 组合与传承` / `## 社会价格`
9. **`information`（信息/秘密 · 同时承载认知母体层卡）**：
   `## 信息内容` / `## 真实性` / `## 来源` / `## 知情者` / `## 传播渠道` / `## 保密/误判` / `## 实际用途`
10. **`event`（历史/世界大事件）**：
    `## 时间与地点` / `## 参与者` / `## 起因` / `## 实际经过` / `## 结果` / `## 长期影响` / `## 关联资料`
11. **`activity`（持续事务/活动）**：
    `## 活动主体` / `## 目标` / `## 地点与时间` / `## 已有行动` / `## 资源与条件` / `## 当前状态` / `## 相关人物与组织`
12. **`technology`（技术/工艺）**：
    `## 技术原理` / `## 掌握者` / `## 材料与条件` / `## 生产/研究过程` / `## 实际用途` / `## 传播与垄断` / `## 产业影响`
13. **`institution`（制度/法律/考核体系）**：
    `## 制度内容` / `## 适用范围` / `## 执行者` / `## 资格与程序` / `## 实际影响` / `## 相关组织与人物`
14. **`work`（作品/文化产品）**：
    `## 作品内容` / `## 创作者` / `## 权属` / `## 发表/发行` / `## 受众与评价` / `## 经济价值` / `## 改编与衍生`
15. **`rule`（世界公共规则）**：
    `## 规则内容` / `## 适用对象` / `## 成立条件` / `## 可观察结果` / `## 例外与边界` / `## 关联能力与社会影响`
16. **`creature`（生物/种族/尾兽）**：
    `## 形态与分布` / `## 生态` / `## 能力` / `## 资源价值` / `## 与人物/组织关系` / `## 历史与社会影响`
17. **`other`（其他）**：
    `## 说明` / `## 相关对象` / `## 历史与关系`

### 2.4 56 组代码登记的标准关系词表（`## 关系索引` 严禁自造词）
每行必须为 `关系名：[[目标1]]、[[目标2]]`，**只用以下登记词**，代码会自动计算双向反向关系：
- **空间**：`位于`、`属于`、`通往`、`邻接`、`控制`、`活动于`
- **人与社会**：`所属`、`所属组织`、`所属家族`、`隶属`、`任职`、`领导`、`上级`、`老师`、`师父`、`父亲`、`母亲`、`父母`、`兄弟`、`姐妹`、`配偶`、`夫妻`、`伴侣`、`朋友`、`好友`、`盟友`、`同盟`、`敌对`、`对手`、`竞争`、`搭档`、`同伴`、`效忠`、`监管`、`出身`、`创建`
- **力量与能力**：`掌握`、`使用`、`传授`、`前置`、`克制`、`反制`、`组合`
- **资产与经济**：`拥有`、`生产`、`加工`、`运输`、`交易`、`消费`、`依赖`、`产于`、`来源`
- **活动与事件**：`参与`、`发生于`、`导致`、`涉及`
- **信息与评价**：`知道`、`来自`、`传播到`、`评价`

### 2.5 「认知母体层卡」专用写法模板（用 `kind: "information"` 规范落库）
每个完整世界至少配备 **4～6 张 `information:cognitive-*` 认知母体专卡**，专门沉淀双母体差值与 Reader-side 高价入口：
1. `information:cognitive-world-stereotypes`：目标男性读者预装的世界刻板印象 vs 原生母体底层真相（**横向差值总图**）
2. `information:cognitive-power-hooks`：读者自动播放的高价能力/物件/资源钩子，以及“可作为能力食物/融合零件/升级引擎”的二次开发玩法（严禁只列招式表）
3. `information:cognitive-character-prices`：自带高 Reader Price 的核心人物与高价女性人物图谱（写清读者为何认她/他、原始关系边与重定价空间）
4. `information:cognitive-faction-conflicts`：读者默认站队情绪、公认痛点与名场面清单（哪些意难平、哪些打脸位、哪些隐藏暗账）
5. `information:cognitive-entry-anchors`：该赛道最经典的切入时间点、经典身份开局与分叉格局（纯认知参考，不写入原生母体事实）

## 第四部分：留给 OpenCode Go 套餐的批量复用 SOP

等 ChatGPT Web 把 `datasets/world-atlas/naruto/` 范本做好后，用 OpenCode Go 套餐（严格遵守白名单：优先免费 `hy4-flash-free` `effort="none"`，长文本/质量要求高切 `glm-5.3-flash` `effort="low"`，避开工作日白天调用 `deepseek-v4.1-flash`）照搬范本，批量重构并做厚其余 15 个世界。

### 4.1 复用步骤（每个世界统一 4 步闭环）
1. **读范本**：让 OpenCode Go 先读取本手册 + `datasets/world-atlas/naruto/batch-01-cognitive-mother.json` 和 `batch-02-konoha-leadership-and-sannin.json` 的前 2 张作为 Few-Shot 标杆。
2. **清理旧打包卡**：凡是此前旧 `batch-01.json` 里存在“多合一打包综述卡”的（如三战合一、四帮合一、三国合一），拆成单一实体原子卡或归档重写。
3. **按 5～6 个微批次生成（每批 10～12 张）**：
   - `batch-01-cognitive-mother.json`：4～6 张认知母体与横向差值卡 + 6 张核心规则/制度单卡；
   - `batch-02-characters-a.json` & `batch-03-characters-b.json`：24～36 张具名核心人物单人卡（含高价人物、关键权力掌门人、典型阵营代表）；
   - `batch-04-locations-orgs.json`：12～14 张单一地点/单一组织/单一职位卡（全部反链具名人物）；
   - `batch-05-power-assets-events.json`：12～14 张单一能力/技术/资源/物品/单一历史大事件卡。
4. **每批生成完立刻跑合规体检命令**：
   ```bash
   npx tsx scripts/import-world-atlas.ts --dir datasets/world-atlas/<worldId>
   ```

### 4.2 强制验收红线（不达标打回重写）
运行 `import-world-atlas.ts` 后，输出 JSON 必须同时满足：
- `totalCardsInWorld`：**≥ 54 张**（主力世界 ≥ 80～120 张）；
- `characterRatio`：**35%～50%**（People-Centered 硬达标）；
- `templatedSectionRatio`：**100%**（每张卡必须带官方 `##` 分节）；
- `registeredRelationRatio`：**≥ 95%**（目标 **100%**，确保双向反向关系索引自动成立）；
- **人工/脚本抽检**：零多合一打包卡、零穿越主角污染、未公开细节不杜撰、不强行编造能力弱点代价、包含独立的 `information:cognitive-*` 认知母体与横向差值卡。
