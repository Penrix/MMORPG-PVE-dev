# 第二模块 · World Atlas 数据库入库硬标准（代码与文档权威版）

本标准直接编译自项目权威文档 `docs/mmorpg/13`、`14`、`15` 与代码契约 `packages/contracts/src/world-atlas.ts`、`packages/persistence/src/source-card-links.ts`。所有通过 `@GitHub` 写入 `datasets/world-atlas/<worldId>/` 的数据必须严格遵守。

---

## 一、原子对象与 People-Centered 铁律

1. **严格一对象一卡（禁止多合一打包综述卡）**
   - ❌ 禁止：`漩涡帮、虎爪帮、瓦伦蒂诺与太平洲帮派生态`、`曹魏、蜀汉、东吴三方政权架构`、`淞沪会战、南京保卫战与台儿庄正面战场`、`蟠桃、人参果、金丹与长生延寿稀缺链`。
   - ✅ 必须：`漩涡帮` 一张、`虎爪帮` 一张、`曹操` 一张、`刘备` 一张、`赤壁之战` 一张、`蟠桃` 一张。
2. **People-Centered 人物中心第一原则**
   - 代码检索优先级第一名是 `character`（具名人物），其次是 `organization`、`position`、`population`、`location`、`resource`、`item`、`ability`、`information`、`event`、`activity`、`technology`、`institution`、`work`、`rule`、`creature`。
   - 每个完整母体世界中，**具名人物卡（`character`）必须占总卡数的 35%～50%**，并且组织/地点/资产/事件卡必须通过标准关系词链接到具体人物（让权力、入口、资产都有“人形接口”）。
3. **客观母体时间轴边界**
   - 仅描述原著/历史的客观母体世界，**严禁写入任何穿越/同人主角**，不锁死单一开书时间点；同一对象在不同历史阶段的状态变化在正文清晰分期写明，原作/史料未公开的精确数值或未定论细节明确标注，不杜撰。

## 三、代码官方登记的 `关系名：[[目标]]` 标准词表（自动计算双向反向关系）

`packages/persistence/src/source-card-links.ts` 只解析独立行 `关系名：[[目标]]`（多个目标用 `、` 分隔）。**必须优先使用下表登记的标准关系词**，才能自动触发代码层的反向关系推导（禁止自造五花八门的长词组当关系名）：

- **空间**：`位于`（反：包含）、`属于`（反：包含）、`通往`、`邻接`、`控制`（反：被控制）、`活动于`（反：活动者）
- **人与社会**：`所属` / `所属组织` / `所属家族` / `隶属`（反：成员）、`任职`（反：任职者）、`领导`（反：下属）、`上级`（反：下级）、`老师`（反：学生）、`师父`（反：徒弟）、`父亲` / `母亲` / `父母`（反：子女）、`兄弟`、`姐妹`、`配偶`、`朋友`、`盟友`、`敌对`、`对手`、`竞争`、`搭档`、`同伴`、`效忠`（反：效忠者）、`监管`（反：被监管）、`出身`（反：出身者）、`创建`（反：创建者）
- **力量与能力**：`掌握`（反：掌握者）、`使用`（反：使用者）、`传授`（反：受传者）、`前置`（反：后续）、`克制`（反：被克制）、`反制`（反：被反制）、`组合`
- **资产与经济**：`拥有`（反：拥有者）、`生产`（反：生产者）、`加工`（反：加工者）、`运输`（反：运输者）、`交易`（反：交易方）、`消费`（反：消费者）、`依赖`（反：支撑）、`产于` / `来源`（反：产出）
- **活动与事件**：`参与`（反：参与者）、`发生于`（反：发生事件）、`导致`（反：结果来自）、`涉及`
- **信息与评价**：`知道`（反：被知晓）、`来自`（反：信息来源）、`传播到`（反：接收自）、`评价`（反：被评价）

## 四、文件结构与 `world.json` 合法枚举

- 目录：`datasets/world-atlas/<worldId>/`
  - `world.json`：`{ "id": "<worldId>", "name": "<中文全称>", "kind": "fictional" | "historical" | "era" | "original_reference", "description": "..." }`
    - ⚠️ **注意 SQLite CHECK 约束**：`world.json` 的 `kind` 只能是 `fictional` / `historical` / `era` / `original_reference` 四选一！
  - `batch-01.json`, `batch-02.json`, ...：每批 **10～15 张独立原子卡**，JSON 数组，每个元素结构：
    ```json
    {
      "entityKey": "<kind>:<english-kebab-id>",
      "kind": "character",
      "name": "规范中文名",
      "aliases": ["常用别名1", "常用别名2"],
      "content": "# 规范中文名\n\n## 身份与人生\n...\n\n所属组织：[[某组织]]\n任职：[[某职位]]\n敌对：[[某人物]]"
    }
    ```
- **内容厚度要求**：每张原子卡正文 **320～550 字**，必须落到真实可演的细节（社会价格、准入门槛、资源/权力流向、人物欲望与筹码、具体局限与冲突引线），绝不写空洞百科摘要。
- **单世界最低数据库深度**：每个主力世界按分层批次累积至 **60～100+ 张独立原子卡**（其中具名人物卡不少于 24～40 张），可持续扩充。
