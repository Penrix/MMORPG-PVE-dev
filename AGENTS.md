## ACTIVE SCOPE AND MANDATORY SEMANTIC GUARDRAIL (2026-11-20)

**Read [docs/mmorpg/10-module2-cognition-and-error-guardrails.md](docs/mmorpg/10-module2-cognition-and-error-guardrails.md) before any change to a world model, database, chronology, cross-IP link or source import.** It records explicit user corrections and previous false assumptions, including WHY those assumptions failed. The user's most recent correction overrides historical design documents.

**LATEST MODULE-2 OVERRIDE (2026-11-21): read [13-world-atlas-lightweight-core.md](docs/mmorpg/13-world-atlas-lightweight-core.md) first for Source World / World Atlas work.** The mother-world Atlas is deliberately lightweight: editable world cards are the content truth; typed wiki links express why cards are connected; `source_relations` is a rebuildable derived index for backlinks, filtering, graph browsing and LLM lookup. Do NOT turn Source World into a professional knowledge-graph, temporal database, relationship-constraint engine, or Project Reality store. Existing Migration 053 specialist tables are legacy/optional assets, not the center of current Module-2 acceptance.

**WORLD CONTENT LANGUAGE (2026-11-21): read [14-world-atlas-content-framework-v01.md](docs/mmorpg/14-world-atlas-content-framework-v01.md) before changing Atlas card kinds, templates or relation vocabulary.** v0.1–v0.7 are the World Atlas **Content Schema**, not the SQL schema: they define what a complete world contains. Stable world objects become cards, stable semantic connections become typed links, rich dimensions stay in card prose/template hints, multi-card structures become derived views, and GM/GOAP/Storylets/Reader Time remain runtime/Novel Studio reasoning rather than Source World fields.

**PEOPLE-CENTERED NARRATIVE AXIS (2026-11-21): read [15-people-centered-narrative-axis.md](docs/mmorpg/15-people-centered-narrative-axis.md).** The ten World Families remain parallel as the content-coverage axis. People-centered is an orthogonal narrative axis that changes graph expansion, retrieval and LLM-context priority, **not** the SQL hierarchy or card storage model. Keep the same Card + Typed Edge graph; prefer concrete people when expanding non-person world content, without inventing NPCs where none exist.

**WORLD BUILDER → ATLAS PRODUCTION CONTRACT (2026-11-21): read [16-world-builder-from-world-atlas.md](docs/mmorpg/16-world-builder-from-world-atlas.md).** First-module generation must name the Atlas cards/relations it is producing. Creating a node is not completion; connect it into the world graph. WorldPack is a candidate/staging batch, not a competing world ontology.

**MODULE-3 WORLD ATLAS ADAPTER (2026-11-21): read [17-module3-world-atlas-integration.md](docs/mmorpg/17-module3-world-atlas-integration.md).** Project Reality is current project truth; Source Atlas is immutable/reference baseline. Use `WorldAtlasStoryContextBuilder` rather than assembling a second world context in individual writing features. Author/narrative/character access are distinct. Settlement remains the single confirmed write path.


**MODULE-3 STORY RUNTIME CORE (2026-11-21): read [18-story-runtime-core.md](docs/mmorpg/18-story-runtime-core.md) before changing story generation, character-agent, director, planning or rehearsal logic.** NarraLume's chapter pipeline is the production lower half, not the story brain. The Module-3 core is now RealityProjection → CharacterObservation → independent CharacterActionProposal → WorldArbitration → speculative Reality delta, plus author-side NarrativeDirector and HorizonRehearsal. Character decisions must be bound to character-visible StoryState; Arbiter may resolve/partially block actions but must not rewrite character intent; forecasts and simulation deltas are speculative and never bypass manuscript Settlement into Canon. The Apache-2.0 `Xiaoyangy/novel-studio` agent/arbitration mechanisms are approved for attributed source adaptation. `AI-Novel-Writing-Assistant` is AGPL-3.0-only with additional commercial terms, so its World Slice ideas are conceptual reference only: do not copy its source into this Apache-based fork.

**MODULE-3 OBJECT-GROUNDED WRITERS' ROOM (2026-11-22): read [20-object-grounded-writers-room.md](docs/mmorpg/20-object-grounded-writers-room.md) first for any S01-S05, idea-generation, Story Seed, Writers' Room, Object Field, Cast Pool/Active Seed, director or story-generation change.** Two author rulings are now hard architecture: (1) **story is designed, not selected from surveillance footage of a self-running world**; S04 is a writers' room before S05 actor runtime. (2) **imagination requires an object**; S01-S04 must start from concrete Module-2 world objects, not free-association and later name substitution. M-methods are search operators, not object sources. Object shortages must surface as world gaps rather than generic invented placeholders.

**MODULE-3 EXPECTATION / NARRATIVE RUNTIME (2026-11-22): read [19-expectation-narrative-runtime.md](docs/mmorpg/19-expectation-narrative-runtime.md) before changing NarrativeDirector, story selection, expectation, scarcity, belief/consensus, Reader Time, payoff or reaction logic.** Layer 1 Reality Runtime answers what can really happen; Layer 2 decides what is worth showing. Scarcity is evidence that makes an outcome socially/causally hard, not a numeric rarity score. Established belief is world/circle/identity/character default cognition grounded in that evidence and expressed through real actions/stakes, not a loose NPC opinion. Expectation is the Reader-visible gap between that established cognition and protagonist advantage. Three-camp reactions must be earned by prior belief/stake/action; never generate post-hoc “shock” as a substitute for setup. Large events are not automatically narratively valuable. Reader Time is allocated to seed, charge, embody, payoff, react and reprice active expectation threads while preserving Character Agent autonomy and Settlement as the only confirmed write path. **Design order and causal order are different:** Layer 2 designs the expectation transaction first (Reader need/emotion, scarcity, established cognition, protagonist advantage, reaction/gain targets, activation focus); Layer 1 then has sole authority over what people actually choose and what Reality actually permits. Layer 2 may redirect, delay or reprice after simulation, but must never predetermine character decisions or force the world to satisfy the design.

**CURRENT TASK OVERRIDE (2026-11-21): Module 3 Novel Studio integration with the accepted Module 2 structure. Read [17-module3-world-atlas-integration.md](docs/mmorpg/17-module3-world-atlas-integration.md).** Novel Studio must consume Project Reality through the shared World Atlas adapter and treat Source Atlas only as reference. Preserve POV/knowledge boundaries: character-bound generation must not receive author-omniscient Project Reality or full source cards. Accepted story changes keep the existing single settlement write path into Canon / Narrative State; do NOT duplicate them into a second Atlas truth store. Module 1 generation is out of scope for this branch. Never spend the current task on changing W0/W1 production, and never treat the completed v0.1–v0.7 original research as prompt excerpts or a set of mandatory one-shot forms. Those seven versions describe the full world content the database must preserve and connect.

**NarraLume already had a pre-writing Story Bible** (author intent, outline, entities, confirmed facts, relationships, timeline, foreshadows), Lorebook, bidirectional post-writing settlement and author review. Do not invent a parallel world database or claim it records only what manuscripts have mentioned.

**Source mother-world reference is not Project Reality**: existing Migration 049 supports multiple corpora per one novel. A protagonist can travel Naruto → Loulan past → One Piece → Naruto inside ONE project with stable identity, a project event sequence and distinct local clocks. Preserve all source history, including late/future material. Source lookup, Character knowledge, Reader knowledge and project-accepted events are separate. Time travel does NOT automatically impose a branch, reset world state, overwrite native source canon or create a new Project.

**Character Fork/Diff rule (2026-11-20):** read [11-world-fork-diff-character-invariants.md](docs/mmorpg/11-world-fork-diff-character-invariants.md). Source mother worlds are immutable reference baselines; Project Reality is a copy-on-write branch and accepted Canon changes are its actual Diff. Original characters retain their evidence-backed core tags and decision patterns; altered events, goals, social relationships and choices are not OOC by definition, while silent persona-core replacement is. Names are not entity IDs. This does NOT yet mean as-of time/branch checkout or same-name storage are fully implemented.

**Original-world wiki priority (2026-11-20):** read [12-original-world-encyclopedia.md](docs/mmorpg/12-original-world-encyclopedia.md). The original Naruto/historical/era encyclopedia must be a detailed, reusable world asset BEFORE any novel. Raw Dattebayo/Wiki datasets are different *evidence*, not different Madara characters. Migration 053 adds source-world professional world content; Migration 054 links multiple raw corpora to one deliberately curated original-world identity. A novel links the curated mother reference; Story writes only to that novel's project Canon. Never auto-merge same-name source records or delete curated source work on upstream reimport.

**Do not reimplement existing Migration 049 or claim new SQL tables prove a world has been fully populated or validated.** Report verified status and outstanding schema/API/test gaps separately.

## Working agreements, current as of 2026-11-20

1. **Task and scope first.** Read the most recent user correction and the code you are changing. This fork uses NarraLume as the complete novel-authoring substrate; World Builder is the main missing business module. Do not reopen the S01–S08 implementation unless specifically requested.
2. **Distinguish implemented from proposed.** The original W0/W1 prompt adapter in Draft PR #1 has now been upgraded to a typed WorldPack pipeline, versioned drafts, graph references, atomic Canon adoption and world-advance prompts. See [current code status](docs/mmorpg/04-world-pack-implementation.md). The initial WorldPack wrapper was self-written, but a set of **actual upstream MIT source modules** has since been transplanted and invoked: Covel parser/source sorter/cache, WorldForge causality/dimension registry, CampaignRepo relationship labels, and SNEQ original deriveBeliefs/salience with a NarraLume witness-history adapter. See [actual ports](docs/mmorpg/05-actual-upstream-ports.md). WorldForge's non-Tauri core including its original Engine, EntityAgent, Arbiter and dependencies has since been ported into `packages/narrative/src/vendor/worldforge/full` and connected to `world.advance` in a candidate-only faction bridge; see [06](docs/mmorpg/06-worldforge-full-engine-port.md). Covel's complete create-world engine and NPC individual GOAP remain unported, and real-model acceptance is still required.
3. **Reuse code, not just names.** Before implementing a module, inspect the verified upstream files in [reuse Crosswalk](docs/mmorpg/01-reuse-crosswalk.md). Decide the exact extraction/interface, source commit, license, tests, and what it adds over NarraLume. Credit upstream code you actually copy; call conceptual references *inspiration* rather than porting.
4. **No duplicate Reality store.** Use NarraLume Canon and the manuscript settlement history as the authoritative accepted world facts. A proposed WorldPack, new NPC activity, M03 creative component, or planned plot is not already-occurred history. Model outputs must remain author-reviewable before promotion.
5. **World creation is not writing an outline.** W0 makes the strategic map of real people, places, resources, institutions and activity. W1 grows detailed content from existing world state using genre × time/place × scarcity; the same world continues when moving to another map. Existing characters and possessions retain IDs/history. People and organizations live and act without waiting for the protagonist. The full original v0.1–v0.7 world research is now authorized and versioned in docs/mmorpg/research; short excerpts do not replace it.
6. **Respect male-reader commercial novel goals.** Produce concrete high-price encounters, access, ownership, pleasure, relationships, advancement and enduring actual gains, not mere labels or perfunctory tasks. Do not redesign away protagonist capabilities with invented costs or silently turn the world into a rescue/business/cooperation checklist. These are creative goals, not permission to invent past factual events.
7. **Peer-level user operations; shared infrastructure.** ① World Builder produces world content; ② World Atlas independently authors/browses source-world cards and their semantic relation index, and can also expose project reference context; ③ Novel Studio writes stories and settles confirmed project facts through NarraLume Canon. Source-world cards are not Project Reality and do not inherit its event/state complexity.
8. **Don't publish private work by accident.** This fork is currently public. The author explicitly authorized publishing v0.1–v0.7 world research, now versioned under docs/mmorpg/research. Do not publish unrelated M03 data, personal content or credentials without permission. Read private material only for the authorized task; put public-compatible abstractions here.
9. **Preserve NarraLume.** Avoid wholesale rewrites of manuscript, review, migrations, editor, or run management. Introduce additive, backward-compatible changes and tests. Don't flatten existing World/Story data into another undocumented JSON format. The legacy Atlas is preserved separately; migration requires identity mapping and provenance.
10. **Verification honesty.** A README/PR, prompt template, compile success, and candidate schema do not prove creative results. Demonstrate true W0/W1 generated packages, authorship/approval to Canon, a novel chapter using those records, chapter-caused state changes, and next-map continuity. Never report CI, real model tests, migrations or deployments as done without a verified result.
