## 2. 下一轮代码工作的依赖关系

```text
原版 NarraLume 正文/Canon/运行底座  ────────────────────────┐
                         │                           │
[A] 可组装的 WorldPackDraft                            │
    Covel 世界包生成/验证协议                           │
    + OnlyWorlds 类型映射                              │
                         │                           │
[B] W0战略底图 / 指定W1区域的真正成套生产器               │
    stable worldId / areaId / 引用 / 来源 / 内容全文      │
                         │                           │
[C] 世界包审阅、修订、分项采用 → 原Canon事务───────────→②│
                         │                           │
[D] 可查询关系图、区域拓扑与地图/人物/组织界面             │
    WorldForge graph + CampaignRepo browser            │
                         │                           │
[E] 自主的NPC/组织活动，事件候选和增量                   │
    WorldForge agent/arbitration + SNEQ认知参考         │
                         │                           │
[F] 小说需要新地区/圈层 ──缺口请求──→ ①增量生产 ───────→③
    已定稿正文→NarraLume章节结算→世界事实状态更新→①/③继续读取
```

**优先顺序**：先解决 A/B/C 的“成套可创作世界”，再做 D 的可见性和 E 的活世界持续行动，最后把 F 作为全流程触发。世界生态要能在 B 开始有具体行动，E 是把已有内容持续运行，不应被误用为“先装模拟器再找创意”。

### A. 复用 Covel 世界包能力（优先级最高）

任务：从一个世界设想或指定区域输入，**生产可以整体阅读和局部编辑的完整世界包**，不只是 N 张实体卡。

- 研究并适配 `create-world` 的动态 schema / 文件路径 / 当前内容类型 discovery，不要求用户自己提供技术字段。
- 建立包级 `WorldPackDraft` 与 `WorldProductionRequest` 契约，含 `worldId/areaId/parentAreaId`、当前世界时间、已确认现状引用、来源、生成范围、实体/关系/事务/资源的跨引用。
- W0 有整体各大区域和社会系统；W1 在已存在区域ID及世界时间下局部深化，不再仅用 `focus` 字符串。
- 打开一个世界包，作者能够看见真实地点、人物、正在做的事、宝物和取得通道之间的关联；可继续深化其中任何节点。
- 用 Covel 的校验思路验证引用/类型/上下游版本和已确认实体的对应；**禁止只做 schema 通过率而不创作内容**。
- 技术上将包级候选映射至 NarraLume Canon，包和单项都有状态，不形成第二套生效 Reality。

**验收**：给定“宗门-坊市-皇城”世界，一个 W0 包包含宗门、坊市、皇城的战略位置、主要力量与有价内容；W1 独立打开坊市后出现真实商会、人物、交易、资产与独立活动，并且每条引用可定位到旧/新ID。任何未采用内容均不污染Canon。

### B. 真实的世界内容生产器

任务：从“字段可以保存”推进为“LLM 真正能生产值钱、能行动的男频世界”。

- 将原私有 v0.1/v0.7 作为**方法来源和评测基准**，不以当前精简提示词取代。必要时通过私有运行环境注入完整研究资料；公开仓库只保留通用适配接口。
- 内容可从任何“已有真实世界对象”展开：地图/组织/人物/资源/活动；允许沿新关系分叉和回返，避免硬性七轮流水线。
- NPC 独立目标、组织运行、可争取资源、力量/资格转换及高价关系不只以“存在这些字段”验收，还须展示行动、权利和Reader能消费的人生。
- 历史/原著恢复与原创合成分开处理资料：史实核对、作品原文、模型推断、原创新增可追溯；历史的未来不能当当前已知事实。
- 不预设必须由男主触发事件，世界始终允许其他人物先采取行动；不自选男主金手指和出生职业。
- 产物按重要内容持续展开，不以“3~6张卡”凑数或限制更强的创意连接。

**验收**：分别生成玄幻、1878法国、1392大明一段可进入的世界。最重要问题是具体人物在同一个现实中做什么、怎样相遇/交易/争夺、男主能以何种特殊优势获得数种实际权益，并能打开下一层人生。不能只展示题材名词和活动标签。

### C. 多类型采用、修订与统一 Reality

任务：把 WorldPack 中的实体、事实、关系、活动作为一组有引用的世界创意**可审阅地写进 NarraLume Canon**。

- 借 NarraLume 原有 candidate/approval、乐观版本/冲突、变更回执、sourceId、Canon引用，不替换原有事实表。
- 世界包采纳前执行引用解析：新实体先获稳定ID；关系/权利/事件能引用包内新实体及已有 Canon ID；确保引用原子性与失败回滚。
- **世界当前事件**、**世界正在酝酿的行动/机会**、**正文已经发生的事件**分别存储，不能全塞进一个 `timeline_events` 并宣称已发生。
- 已经存在的实体继续保持 ID；世界包再次生成或换地图时只增量变化，不能改名伪造新身份。
- 支持作者修订内容而不是只有一键通过/拒绝；保留修改差异和来源。
- 保留旧Atlas `entries/facts/links/arrangements` 到新 Canon 的迁移映射与一次性/增量同步日志，不覆盖旧原件。

**验收**：新增世界包含某组织、负责人、宝物、所有权和活动。作者只采用其中部分，系统准确处理引用依赖，旧 Canon 与正文均不被候选污染；后续生成同一区域仍认得同一个人、组织和宝物。

### D. 图关系与可浏览的世界地图

- 用 WorldForge graph traversal 的带时间关系查询与事件级联投影，**基于现有 Canon 事实生成**邻接查询，不再造第二份可独立矛盾的关系数据。
- 用 CampaignRepo Wiki、地图点位、双向链接的浏览体验作为交互参照，转为 NarraLume React 组件与 API。
- 任何人物能跳转其组织、日常活动、权利中介、现持有资源与相关地区；任意地区可打开其市场/社会入口；可按指定时间回查关系。
- 未来 S 系列若接入，也复用该关系索引，不重建新的实体主键体系。

**验收**：在坊市商会人物卡上能导航到控制的货源、背后的家族、拍卖场、雇佣关系及可以进入更高圈层的实际中介；更改一件事后关系图和章节语境能按当前状态查询。

### E. 独立生活 / NPC活动机制

- 先选重要或活跃的 NPC / 组织；从世界实际关系、资产和个人所知装配上下文，借 WorldForge `runEntityAgent` 形式产出行动/事件候选与delta，再由仲裁/采纳后进入历史。
- 大部分日常生活不需逐日显式运行。目标是**当故事时间推进/男主离开旧地图/作者指定时**，世界可信地继续发展，并在回访时产生新价格、关系和事件。
- SNEQ 的事件事实投影/知情传播只作为补强 NarraLume 现有知识记录的机制候选，不要替换现有唯一 Canon。
- 资产账与权限变化必须有具体来源和作用对象；“状态更新”不等于偷偷收取升级代价或撤销男主已赢得的资产。

**验收**：男主离开坊市后，原商会仍有自己的业务，师父、旧友、竞争者各自推动事情；两个月后返回能看见与此前状态连续的变化，而不是重新随机生成一批陌生NPC。

### F. 双向协作：第三模块需要世界时直接调用第一模块

- 小说工作区发出 **WorldContentGapRequest**（已有区域ID、故事时间、具体缺失对象、触发原因与作用范围）；①可独立从作者入口启动，也可响应此请求。
- 世界包采用后，③重新编译当前世界上下文并**从之前中断的故事位置继续**，不重开一部小说。
- 正文正式采用后使用 NarraLume 原本的章节结算：事实、关系、时间线和知情差量回写Canon；①在下次世界生产前读取这些实际变化。
- 对同人/历史题材，改编新内容与可核查史实身份要可见；旧世界资产、秘密和Reader已知信息不会因进入新地图重置。

**验收**：宗门章→进入坊市时缺商会与拍卖场→①补世界包→②采用→③继续原章→男主在正文获得店铺产权→②确认新事实→下次生成皇城地图时仍保留店铺产权与商会关系。

## 3. 三种不同的检查，不能互相冒充

| 检查          | 检验什么                                                           | 不代表什么                                 |
| ------------- | ------------------------------------------------------------------ | ------------------------------------------ |
| 构建/自动测试 | TypeScript无类型错误、API格式正确、包引用与迁移事务可运行          | 不等于世界值得进入、人物有戏               |
| 生成实演      | 真实LLM能生产具体地图、势力、生活、资源、相互作用和高价人事物      | 不等于数据库、写回和长篇已跑通             |
| 小说闭环      | 真实世界被查询→章节生成→采用→事实变化→再次世界生成→同一Reality继续 | 不等于百万字已长期稳定；需要更长的持续样本 |

实际开发应以**可检查的成果**交付。一个阶段的工具安装或文件数量多，不能替代上述结果。

- 暂不把新的 S01～S08 架构作为第一模块开发的前置条件。后续真实创作样本证明 NarraLume 本身的故事组织不足时，再以具体缺口决定增强什么。
