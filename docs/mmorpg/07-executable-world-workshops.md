# MMORPG 第一模块｜可执行世界生产工序（2026-11-20）

> 这份文档针对用户纠正：**借鉴文字冒险、MUD 与 MMORPG 世界设计，把 v0.1～v0.7 的世界制作方法转为程序控制下的文字设定集生产；不是开发真正可操作的游戏，也不是让模型阅读几个提示词后自行发挥。**
>
> 状态：第一批程序控制与可执行玩法路径已提交；不是整套 v0.1～v0.7 已经实现，也不是完整 MMO 引擎。检查 CI 结果时应使用当前实际 commit。

## 代码现在会做什么

- [世界生产控制器](../../packages/narrative/src/world-production-engine.ts) 根据已经存在的对象、组织关系、资产持有、独立活动和可执行通道发现*实际缺少的世界内容*；返回一个绑定具体对象的制作工单。W0/W1 对同一身份增量扩展，不是套固定模板。
- [世界工序运行器](../../packages/narrative/src/world-production-runner.ts) 由程序调度地理/势力/人物/经济/力量/事件/社会通道/可玩性工序。每一工序必须产生对应的实体、关系或可执行动作，不允许模型自报“模块完成”。动态缺口能插入、回返、重新生产。核心是**建立世界关系与行动**，不是章节剧情摘要。
- [世界游戏动作运行时](../../packages/narrative/src/world-action-runtime.ts) 执行 **仅在沙盒中的** 可用性与多路径探索：输入已有资产/权限/能力/知情/准入状态，按具体行动前提找到能做的事，返回潜在新资产/通路以及下一步操作。任何模拟产出都没有直接写入 Canon。
- [WorldPack 动作数据](../../packages/contracts/src/world-pack.ts) 扩充了 `interactions`：谁提供机会、地点、具体动作、前置资格/资产、可能得到什么权利/新资源。模型无权捏造新身份引用；关系由程序校验。
- [采纳接口](../../packages/services/src/world-pack-routes.ts) 将作者确认的可用行动写成 `world.affordance` 事实，**不是**将动作的未来收益直接送给男主。
- [原 NarraLume Checkpoint](../../packages/persistence/src/run-repository.ts) 现在每个成功世界生产工序都保留进度快照，AI 调用异常重试不应从第一工序再做一遍。
- [世界生成工作台](../../apps/web/src/workspaces/world-builder.tsx) 展示执行过哪些工序、其实际变更、具体前置条件及多步取得路径。不是把模型一句“我已生成十模块”当完成证据。

## 统一生产原则（由作者明确纠正）

- **同一套 v0.1～v0.7 世界方法**适用于原著/同人、历史、现实都市与完全原创；已有材料影响证据和世界事实的可变更范围，**不构成不同生产流水线**。
- **世界规律分叉只有两类**：现实与社会力量；存在超凡规律的世界。两类都要制作真实的组织、人物、资源、时间、事件与高价值内容。超凡世界在共同框架上增加 v0.3 的专项制作。
- **文字世界设定集是最终产物**。每个对象保留给人和 LLM 阅读的具体文字正文，并有稳定 ID、归属、权利、位置、人物、关系与状态供程序使用。不要把动作 JSON、模拟器或任务链当成世界本身。
- **程序控制 LLM 的工序与完成证据**。模型负责创造，而不负责宣布本模块已做完、忽略深度、重写旧对象或随便终止。开放状态机允许从已存在的人物/组织/地点/资源/力量进入、分叉、回填，而非只按地图起步。
- **现有完成范围有限**：这轮已纠正源材料分叉、W0 社会力量缺失、固定地图入口和两步游戏动作链的强制验收；但不能因此宣称已将七版完整方法程序化。下一步优先深化真实文字世界内容的制作分辨率及其因果和关联验收。

参考源码：[统一世界规则](../../packages/narrative/src/world-design-policy.ts)、[世界工序运行器](../../packages/narrative/src/world-production-runner.ts)、[世界内容缺口检查](../../packages/narrative/src/world-production-engine.ts)。

**不能用“测试字段齐全”取代小说世界的实际进入与回访验证；但无需运行一款真正的游戏。** 当前单元/API 测试主要使用 Mock 模型，依次检验世界内容真实关系、沙盒行动路径、状态继承、数据库断点和写作上下文；真实模型能否产生好用、有社会价格、可持续演法的游戏世界，尚需另行实演。

## 程序如何处理一个具体对象

```text
指定世界 / 地区 / 组织 / 人物 / 资源
  ↓
读取旧Canon + v0.1～v0.7已确认世界规则
  ↓
实际世界图 → 当前对象的游戏内容生产工单
  ├─ 地区还没有运营组织 → 生产组织的实际业务与辖区
  ├─ 组织没有真实人物 → 生产负责人、雇员与私人关系
  ├─ 人物没有可争取资源 → 生产资产控制与取得路径
  ├─ 资源不能带来行动 → 生产使用、交换、经营和升级机会
  ├─ 人物没有自己的事务 → 生产独立目标与行动
  ├─ 世界只有地名没有社会通路 → 生产真实中介/资格
  └─ 实际内容不足以让人物生活/争取/变化 → 沿该世界对象继续制作
      （可选用文字游戏行动链作局部检验，但非整个世界的强制完成条件）
  ↓
每次必须产生实际对象/边/动作，并保留Checkpoint
  ↓
文字世界试进入：是否有具体人事物、活动、社会价格与后续展开？
  ├─ 不行 → 对实际缺口再发工单，回到当前对象
  └─ 能 → 形成可审阅世界包
  ↓
作者采纳 → 唯一Canon，不自动平仓未发生的收益
```

## 目前绝对不能宣称

- Covel 原 `create-world.ts` **完整生成/校验主体未移植**；目前原版解析、缓存、来源排序已经移植使用。
- WorldForge 的组织 Agent 是移植源码，**个人 GOAP 与可证明连续的完整模拟世界**尚未完成。
- v0.1～v0.7 原文保存及方法引用不等于已经实现它们所有的设计思想。
- 目前程序编排已经可测试，但尚不能证明一部长篇连续百万字的 MMO 内容生产和运行已被真实模型验收。

下一阶段重点是继续把 v0.1～v0.7 的**世界设计与具体游戏内容制作方法**逐项转成可调用、可验证、可恢复的生产工序：区域、人物生态、机构业务、资源产业、力量与Build、玩法与生活、信息传播、个人目标、历史回访。文字 RPG 行动模型、GOAP 和 GM 仅作为帮助生成及检验文字世界的工具，不作为整个第一模块的交付目标。
