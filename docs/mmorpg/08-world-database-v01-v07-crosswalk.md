## 2026-11-20 语义纠正｜多母体与跨世界/时间旅行共存于一本项目 Reality

**权威来源：Library《男频语义内核 v1.3》126～135、141 节，及《从火影开始掌控时间》跨世界公路对标。**

### 本体边界（禁止从开书时间、来源作品数量推断项目数量）

- **原生母体（Source Reference）**：火影、海贼、漫威、史书、唐宋元明清或某个年代，均是供小说取用的原生事实、规则、人物、历史、社会价格和因果惯性的**资料**；可有多个母体同时服务一本书。原著未来全量存储，但只有在项目 Reality 中实际成立才能取得项目当前事实权。
- **认知母体（Reader Prepricing）**：Reader 对 IP、人物、能力、制度和时代的预装价值、共同期待和价格判断。不是“原著设定表”的别名，不自动等于世界客观事实。
- **项目世界（Project Reality）**：整本小说只有一份持续承认 Story 已发生结果的项目 Canon。它完全可以同时包含多个宇宙/地图/时间段/历史分支。**一个项目世界 != 一个原著世界 != 一个时空地点**。
- **Current Reality**：在当前故事进度、某个具体位置和世界时间里仍有因果权的事实切片。全量世界数据库不因开书时间、男主位置、当前人物的认知而删减。
- **穿越/时间旅行**：是人物跨位置、世界、时间和可能的历史分支发生的**项目事件**，带着身份、资产、知识、关系、能力、变化结果；它不是创建新小说项目的命令，也不是自动发金手指或强制建立平行分支的命令。
- **Story Writeback**：所有已发生事件最终写到这一份项目 Reality。火影与海贼源材料的原著 Canon 不被更改；其他项目也不被串改。当前项目内旧世界人物离场后仍可变化，下一次进入需按项目状态回访。

### 两个不能回避的反例

1. 一本书男主从火影进入海贼，后来返回火影：既不是“火影项目+海贼项目”，也不是“在海贼重新创造男主”。同一个男主 ID，其忍术、霸气、财物、伙伴、知识和历史随实际事件变化。两套源资料均可长期查询，Project Canon 只有一个。
2. 男主借楼兰龙脉在火影内部前往过去，又返回未来：一件事件至少需要写出**项目行动顺序、出发时空、抵达时空、来源历史参照、实际改变以及返回规则**。是否改写原时间线、形成新历史分支或闭环，由作者/作品已有设定决定；数据库不能擅自替小说选定机制。

### 现有 NarraLume 的**真实工程缺口**（不可说已解决）

- **历史缺口与现行纠正**：原版 `canon_entities` 曾使用 `UNIQUE(project_id,type,name)`。Migration 050 已有源实体映射，052 改为支持可选 `world_scope_id` 的世界范围唯一性，同时维持人物稳定 Canon ID。单独的时间实例仍由 050 的显式实例表处理。迁移兼容性必须通过旧数据/全文检索/外键测试。
- `timeline_events.story_time_start/end` 为单组字符串；没有**项目事件顺序 × 目的地本地时间 × 历史分支** 的明确结构。
- `canon_entities/project_id` 与 `world_lore_bindings` 保留项目隔离是对的，但还没有**多个共享原生母体对一个项目的只读参照和差异化继承**，不能把每换原著就新建项目当补丁。
- 现有 `world_chronicle_links`、组织、声望、信息、权利等专项表已经有用途，但**没有跨时空的统一实体实例/事件定位与查询语义**，不能凭表多声称“多世界已支持”。
- 一项事实**在原著资料中成立**、**在项目某时间某位置成为现实**、**被男主知道**、**被 Reader 看见**是四个不同判断，不能用一条 `current` 或单个 `source_type` 混为一谈。
- 一个角色的**源身份**、项目中的**唯一连续人物**、在某个过去时点可能相遇的**同时存在的个人实例**不是无条件同一个数据库行。没有需要区分时无需强拆，有实际同场双重个体/分身时必须表示。
- 一个高价人物在母体中天然昂贵，和男主有无接近、合作、获取其资产是不同事实。不能用单一 `potential→realized` 进度表示“这个人是否值得写”。

### 下一次数据库修改应该先验证的四条接口行为

1. **一个 project 加载多个 source corpus**；各母体内原著和历史原文完整保留，项目只继承、引用和改写自己的事实。
2. **同一男主跨火影/海贼往返**：资产、能力、因果、关系沿同一个人物 ID 及事件串追踪；场所/本地时钟可以不同，项目的 Story 事件顺序不丢。
3. **楼兰时间穿越**：同一空间不同时点、可选历史分支、源历史与项目改变按事件和权限区分；不得自动选择分支或自动恢复原著未来。
4. **前瞻/回访查询**：源母体历史全量可见；项目世界事实依据实际发生取得权威；人物只知亲历/得知部分；Reader 可展示的内容独立维护。

**进度更新：在原先 049 多原生母体资料基础上，已新增 050 的项目身份/时空关系与穿越事件，实现第一批查询和 API，并为两个世界与楼兰写回建立自动测试。047/048 的专项世界表和 050 都不等于完整世界设计 v0.1～v0.7 已全部数据库化，当前实装与剩余缺口见下。**

**本轮优先交付的验证**：`project-world-repository.test.ts` 检查火影→楼兰过去→海贼→返回火影只有一个男主和一个小说项目、故事事件顺序与本地年代不同、没有强制建支线、原生资料未被写回；`project-world-api.test.ts` 验证公共服务接口；数据库跨项目引用和导入项目隔离必须通过。

### 新增 Fork/Diff 工作模式（2026-11-20）

作者进一步明确：**原生母体可视为基线，项目世界是 Fork，故事产生实际差异；原著人物人格标签不能无故改变，否则会发生 OOC。** 完整定义与验收见 [11：世界 Fork/Diff 与人物核心锚点](11-world-fork-diff-character-invariants.md)。

- **051** `project_character_anchors` 锁定经作者确认的人格标签/判断倾向，不让正文结算自动覆写；`project_fork_claim_baselines` 只固定真正选定、能溯源的原生字段，实际改变继续写 NarraLume Canon。`SqliteProjectForkRepository.diffEntity` 读取基线、确认事实和变化，绝不把“没有本项目事实”直接说成“原著未来都已经发生”。
- **052** 为不同世界的同名角色保留真实名字，并用可选 `world_scope_id` 消歧。不把不同世界同名人物自动认作同一个人；具体对应还要查 049 Source Corpus 与 050 Project Source Identity。
- **Checkout 仍缺**：按指定故事事件序号 + 世界坐标 + 时间分支准确恢复所有事实和社会状态，目前并未因 Fork/Diff 第一版就自动解决。

## 第一裁决：一个世界，四层相互连通的数据

1. **Identity / World Object**：人物、场所、组织、物品、规则、概念沿用 `canon_entities.id`，从宇智波斑和宇智波一族互相查询，而不是独立复制传记。
2. **Readable Lore / Dossier**：长篇人物传记、组织史、建筑、制度、生活和完整能力描述继续使用 `lore_entries.content`。新增 `world_lore_bindings` 将每篇正文绑定具体 Canon 对象与 facet，不能只靠关键词碰运气。
3. **Reality / Relationships / Events**：客观世界事实、产权、身份、行动、时间、角色关系分别沿用 `canon_facts`、`relationship_events`、`timeline_events` 和 `timeline_participants`。一项事件只有一个稳定事件 ID；世界编年史是事件投影，不能在每个家族各造一份真相。
4. **Typed World Facets / Crosswalk**：对 v0.1～v0.7 真正具有不同语义的社会运转、立场、组织职权、评价与稀缺价值，新增专门关系表，字段连接回同一 Canon ID。候选尚未确认为事实，不自动拥有资产、法权和他人感情。

不要为 WorldPack、Lorebook、游戏运行时再建互相竞争的 Canon。第一模块只提交候选设定；第二模块完成关联、采纳、时间和事实维护；第三模块从此读取并回写**实际发生**的改变。

## 宇智波一族：不能再是四字段卡

**以下是“数据库应该能表达的结构”，不是当前库里已经导入、逐条核实的火影原著内容。** 时代顺序、具体权利、角色立场均需对原作/资料作证据确认；同人新增或分歧必须与原著事实分开。

### 一张组织资料应该能打开以下完整世界

```text
ORG-UCHIHA｜宇智波一族（Canon唯一 ID）
  ├─ 文字设定
  │    ├─ 氏族源流与发展（完整史料正文）
  │    ├─ 历代领袖与分支世系
  │    ├─ 居住、家庭、教育、婚姻、普通族人生活
  │    ├─ 忍术训练、族内技术/秘术、商业及社会角色
  │    └─ 内部派系、利益和长远目标（按时代变化）
  ├─ 编年史（时间顺序连接 SAME timeline_events）
  │    ├─ 战国时期：宇智波斑、与千手一族的关系
  │    ├─ 建村时期：斑与柱间的关系，村落创立
  │    ├─ 警务制度形成：制度授予何种职责、辖区和决定权
  │    ├─ 九尾事件之后：不同方收到什么消息、如何评估家族
  │    ├─ 政治矛盾及家族内部立场
  │    └─ 灭族及后续（原著母体全量保存；项目中何时、是否发生，由当前项目 Reality 决定）
  ├─ 组织机器
  │    ├─ 类型：氏族/家族网络（不同于行政官署）
  │    ├─ 决策：族长、内部会议、人员任命、继任
  │    ├─ 关联职能：木叶警务部队（独立组织，不能等同氏族私产）
  │    ├─ 财源、族地、训练资源、实际资产与权属
  │    └─ 现阶段谁能决定、谁执行、哪些事无权决定
  ├─ 关系网络（复用关系事件与事实）
  │    ├─ 人物：斑、富岳、鼬、止水、其他实际人物
  │    ├─ 组织：木叶政权、警务部队、千手相关人物/组织
  │    ├─ 能力：写轮眼、其他具体忍术与特殊能力
  │    ├─ 区域：木叶、族地、机构所在场所
  │    └─ 职权、产权、社会中介和被保密的信息
  ├─ 声望/社会价格（由不同评价方分别记录）
  │    ├─ 忍术及战斗领域的专业评价
  │    ├─ 村政高层的政治信任/威胁判断
  │    ├─ 警务制度中的职务权限（不是等同声望）
  │    └─ 普通居民或他族的公共印象（要有传播途径）
  ├─ 立场（不是“宇智波全族反木叶”）
  │    ├─ 一族公开政治诉求
  │    ├─ 族长在具体历史阶段的判断与行动
  │    ├─ 斑、鼬、止水等不同人物的真实个人目标
  │    └─ 对同一政策争议的相互矛盾立场
  ├─ 高价人物 / 资产 / 权力中介
  │    ├─ 斑：历史地位、实际力量、思想与关系，不因其重要就可召唤
  │    ├─ 止水：个体能力、社会关系、别人愿付出的实际价格
  │    ├─ 富岳：族长身份实际能决定什么及其制度限制
  │    ├─ 某项岗位/机构：谁可以任命、谁能否决、通过什么程序
  │    └─ 写轮眼：血继限界不是抽象“很强”，需要能力事实和取得边界
  └─ 当前 Reality
       ├─ 开书时点，族人、权力、关系、各事务实际处于什么状态
       ├─ 哪些事件已经发生、哪些还只是未来史/预测/同人分歧
       ├─ 各人物脑中不同的情报版本
       └─ 因小说新事件产生的事实/评价/立场/组织改变
```

### 跨对象查找应该真实成立

- 从 **斑** → 战国氏族领袖身份 → 一族历史 → 木叶创立相关事件 → 千手柱间及关联的政治分歧。
- 从 **富岳** → 家族身份/职位 → 权力范围 → 族内组织治理 → 木叶警务职能 → 村政高层的评价与限制。
- 从 **止水** → 技能、关系、秘密知识 → 被谁重视及为什么 → 谁实际知道哪些情报 → 可能影响哪些决策。
- 从 **木叶警务部队** → 它的正式职责、职权依据、成员岗位、责任对象 → 一族的历史参与，而不是“整个警务部队属于家族财产”。
- 从 **木叶村** → 控制地图、社会地图、信息地图 → 家族位置、人口生态、职权制度、人员与事务。
- 从 **写轮眼** → 有效规则、阶段、使用者、适用情景、组合及反制、社会定价、取得与传承。

这些查询必须复用同一实体/事件/关系 ID，不能把每种视图变成完全独立的角色卡。

### 关于七版的真正边界

v0.7 的原话强调：**“同一个世界状态，不重新制造八本不连通的账。”** 这一要求与 SQL 规范化、复用 Canon 唯一对象及事件 ID 完全一致。不能因为 v0.6 出现“社会评价账”“人物记忆账”就单独复制出三份宇智波历史事实。

v0.2 则明确需要**组织图、资产控制图、现行决策权限表、派系利益图、势力互关图、具体事务进度**。因此 047 的组织/政治/社会权力切面是必要的第一步，但还缺专门经济、能力、地图和制度数据模型。

## 已实装的第一批 SQL 结构（迁移 047）

- `world_lore_bindings`：Lorebook 章节 ↔ Canon实体 + facet。
- `world_chronicle_links`：同一 timeline_event ↔ 宇智波等不同对象的历史意义；可复用原著事件顺序。
- `world_organization_profiles`：氏族、组织、派系、联盟、社会场域的类型与治理/继承/资金/任务。
- `world_organization_functions`：内部子机构、职位实际持有人、职责、辖区、资源和决策边界。
- `world_stances`：对具体政策/问题的个人或组织立场、利益和行动，保留时间与可见性。
- `world_standings`：由不同评价方在不同维度认定的声望与社会价格，和已发生的实际回应分开。
- `world_power_channels`：持有人→中介→权限机关→实际可影响对象；必须写明不能自动授予什么。
- `world_value_appraisals`：重要人物、组织职位、技能、资产的稀缺与价值，标记可能/争取/实现，不提前记账。
- `world_organization_dossier_index`：组织档案检索汇总视图，回溯 Lorebook / Timeline / Canon。

`SqliteWorldEncyclopediaRepository.getDossier(projectId, entityId)` 一次返回一个实体的长文本、历史、组织、立场、评价、高价对象、权力中介和 Canon 事实/现行关系。HTTP 查询入口：`GET /api/projects/:projectId/world-encyclopedia/:entityId`。

这些是**可保存/查询结构**，不是说我们已经把火影原著数据填进去。下一阶段的目标不是继续加概念字段，而是按上述 Crosswalk 优先补足 **四张地图、完整组织及人口/产业、超凡力量能力网络、信息传播/社会评估的事件演变**，然后用同一宇智波资料样本反复查询，不让历史与实力关系被压缩。

## 已实装第二批 SQL 结构（迁移 048）

原有 `canon_entities`、`canon_facts`、`timeline_events` 和 `relationship_events` 仍为**唯一已采纳事实与历史的底座**。以下是可查询的专项世界结构，而非第二套世界事实：

- `world_map_edges`：每条世界通道属于物理、控制、社会、信息四张图之一，连接实际对象、实际中介、准入条件、时间状态与证据；同一个地点不会因为四张地图而被复制四次。
- `world_capability_profiles`：现实/超凡力量共用的实际机制、动作、生效范围、条件、反制、训练或取得方式和社会影响。避免把“写轮眼”仅保存为一个标签。
- `world_capability_links`：技能/规则间的先决条件、组合、反制、改善、质变、传承、许可和实际使用者，指向原 Canon ID。
- `world_production_links`：资源/能力等对象如何由实际组织和个人提取、培养、制造、加工、运输、交易、消费、修复和分配；同时连接产地与加工者，不用一行“家族有资源”代替。
- `world_information_flows`：以 `canon_facts.id` 为所传播的事实，谁通过什么载体、在什么时间告诉谁，接收者知道、相信、怀疑或误解的版本。不能因事实已被记录便推定全村知道。

对应 [048 SQL迁移](../../packages/persistence/src/migrations/048-world-map-power-production-information.ts)、[世界结构查询接口](../../packages/persistence/src/world-structures-repository.ts)。这五类专项查询已经合入 `SqliteWorldEncyclopediaRepository.getDossier` 的统一世界档案入口，测试使用宇智波/木叶与写轮眼的跨对象资料验证。

## 完成标准（对第二模块）

1. **查组织如宇智波一族**：返回完整编年史、组织职责、族长与高价人物、警务权力边界、多评价方声望/立场、关联血继限界和各种资源。跨查询追人、组织、能力、事件，结果身份一致。
2. **查人如宇智波斑**：返回其个人历史、与一族/柱间/木叶关系，事件发生时点；不把建村后所有人的知识、立场追溯给历史前期人物。
3. **查机构如木叶警务部队**：返回正式职权、实际决策/执行、人员、工作地点、资源与制度依赖；既不能等同整个氏族也不能等同村政。
4. **查时间**：完整资料库始终保留母体全历史；按查询目的返回原著参考、项目已发生历史、某地点某时点的有效 Reality、具体人物知识或 Reader 展示知识。原著未来不自动成为项目事实。
5. **查来源**：每个具体历史或能力事实应能定位原著、资料、作者确认或原创候选。不把 AI 补全当成官方既有事实。
6. **查演变**：如果小说改变了制度、人事、声望与资产，沿同一事件编号更新相应视图，旧历史仍可追溯。

**现状**：第 1 项已经有初步关系结构与查询接口，其余部分只有部分可用能力。完整合格仍需实测和持续扩建。
