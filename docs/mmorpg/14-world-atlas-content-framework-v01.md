# 第二模块｜World Atlas 世界内容框架 v0.1（2026-11-21，当前权威）

> **用途**：把 `v0.1～v0.7` 七版 MMORPG 世界设计研究，编译为第二模块可以长期承载的**世界内容语言**。
>
> 本文不是 SQL Schema，不要求为每一项新增数据库表，也不是第一模块的生成流程。它回答的是：**一个完整世界里应该存在什么类型的内容，这些内容怎样以卡片和关系进入 World Atlas。**
>
> 存储原则继续服从 [13：World Atlas 轻量核心](13-world-atlas-lightweight-core.md)：**卡片正文是资料真相，typed links 表达关系，关系索引可从卡片重建。**\n>\n> **两轴补充：** 十个 World Family 在本文中继续作为并排的**内容分类轴**。小说叙事中的“People 为中心”不是数据库层级替代，而是第二条正交的 View / Query / Priority 轴，见 [15：People-Centered Narrative Axis](15-people-centered-narrative-axis.md)。

---

## 0. 最高裁决：七版研究是 Content Schema，不是 Database Schema

七版研究的关系是“同一棵树不断长大”，不是七套相互竞争的字段表。

- **v0.1** 给出世界骨架：地图、势力、人物、力量、资源、事件、成长、动态世界、社交、高阶内容。
- **v0.2** 把骨架做实：四张地图、组织机器、NPC生活、产业链、权限、世界自转。
- **v0.3** 补全超凡世界：能量、境界、技能、传承、反制、修炼资源、战斗和社会用途。
- **v0.4** 分开世界公共规则、人物实际 Build、特殊优势/金手指。
- **v0.5** 把“世界存在”推进为“世界可玩”：Affordance、探索、遭遇、物品、家园、旅行、回访。
- **v0.6** 补社会认知：事实、人物认知、信息传播、社会评价、长期记忆、Reader Knowledge。
- **v0.7** 补开放运行：Player Agency、GM、GOAP、Storylets、系统交互、研发与社会演化。

因此：

> **v0.1～v0.7 决定 World Atlas 要能容纳和连接哪些世界内容，但不要求把每一章翻译为 SQL 表或强制字段。**

## 1. 世界的十个内容家族

这十个家族是作者和 LLM 的**世界认知目录**，不是十张数据库表。它们在内容覆盖意义上保持并排，不因为人物是叙事中心就把其他九类降成数据库子节点。

| 内容家族                      | 世界里真正有什么                                                   | Atlas 中主要怎样存在                                     |
| ----------------------------- | ------------------------------------------------------------------ | -------------------------------------------------------- |
| **SPACE 空间**                | 世界、国家、区域、Zone、Hub、POI、道路、航线、社会入口             | 地点卡 + typed links                                     |
| **PEOPLE 人**                 | 人物、人口/职业群体、种族、生物                                    | 人物/人口/生物卡 + 关系                                  |
| **ORGANIZATION 社会组织**     | 正式组织、派系、联盟、家族网络、制度、职位、权限                   | 组织/制度/职位卡 + 关系                                  |
| **POWER 力量与规则**          | 公共力量规则、能量、境界、技能、功法、忍术、专业能力、技术         | 能力/规则/技术卡 + 前置/掌握/反制等关系                  |
| **ASSET 资源与资产**          | 资源、物品、财产、权利、作品、知识、秘密、高价对象                 | 资源/物品/作品/信息卡 + 权属关系                         |
| **ECONOMY 生产与流通**        | 产地、生产、加工、运输、交易、消费、分配、产业链                   | 多种卡片之间的生产/运输/交易关系网络                     |
| **ACTIVITY 世界活动**         | 历史事件、当前事务、战争、商业、政治、研究、私人活动、日常         | 事件/活动卡 + 参与/发生于/导致关系                       |
| **INFORMATION 信息世界**      | 事实、情报、传播渠道、秘密、人物认知、误判                         | 信息卡 + 知道/来自/传播到等关系；项目运行态另归 Reality  |
| **VALUE 社会定价**            | 公众名望、专业评价、组织立场、私人信任、威胁判断、稀缺价格         | 主要存在于人物/组织正文与关系语义；不是全局好感数值表    |
| **PLAYABLE CONTENT 可玩内容** | 可探索、可学习、可争夺、可经营、可交往、可享受、高价机会、高阶世界 | 是对前九类内容的**可进入视图和组合**，不是独立数据库实体 |

### 1.1 重要边界

- **Endgame 不是实体**：它是更高价地点、人物、组织、能力、资产和生活的组合。
- **Progression 不是实体**：它是能力、资格、职位、资产、地区之间的可达路径。
- **Social Gameplay 不是实体**：它是人物与人物/组织/家族/地点/权限之间的关系网络。
- **Living World 不是 Source World 的卡片类型**：它是项目故事实际发生后的 Reality 状态。
- **Economy / Value / Playable Content 很多时候是“看世界的视图”**，不因为研究中有独立章节就强制建专表。

## 2. Atlas Card Type Registry｜真正适合独立成卡的对象

Card Type 是轻量分类，不是强制模板。卡片正文始终可以自由增长。

### 2.1 第一批正式 Card Types

| Type           | 中文          | 典型对象                               |
| -------------- | ------------- | -------------------------------------- |
| `character`    | 人物          | 旗木卡卡西、某编辑、某将军             |
| `population`   | 人口/职业群体 | 木叶普通忍者、巴黎排字工、某地区佃农   |
| `organization` | 组织          | 木叶隐村、宇智波一族、出版社、银行     |
| `institution`  | 制度/机构规则 | 忍者任务制度、科举、版权制度           |
| `position`     | 职位/身份位   | 火影、上忍、报社主编、某官职           |
| `location`     | 地点/区域     | 火之国、木叶、训练场、巴黎报业区       |
| `ability`      | 能力/技能     | 写轮眼、雷切、炼药术、专业写作能力     |
| `rule`         | 世界规则      | 查克拉规则、继承规则、法律程序         |
| `technology`   | 技术/工艺     | 印刷技术、封印术体系、炼器技术         |
| `resource`     | 资源          | 矿脉、查克拉金属、纸张渠道、资本       |
| `item`         | 物品/资产     | 忍刀、房产、契约、秘卷                 |
| `work`         | 作品/文化产品 | 小说、剧本、歌曲、报刊栏目             |
| `information`  | 信息/秘密     | 情报、传闻、秘密身份、已知线索         |
| `event`        | 历史/世界事件 | 神无毗桥之战、政变、并购、婚礼         |
| `activity`     | 持续事务/活动 | 战争进行中、研究项目、连载、训练、调查 |
| `creature`     | 生物/种族对象 | 尾兽、魔兽、特殊种群                   |
| `other`        | 其他          | 尚未稳定归类但值得独立成卡的对象       |

这些类型可以继续增删，但必须满足一个问题：

> **它是否真的是世界里值得单独拥有稳定身份、长文字资料和关系网络的对象？**

如果只是某种“观察方法”“玩法视图”“运行算法”，就不应该为了对齐理论而增加 Card Type。

## 3. 卡片模板只提供“建议关注点”，不提供强制字段

### 3.1 人物卡

建议关注：

- 身份、人生阶段、所在地点
- 职业、家庭、财富与组织位置
- 性格、判断倾向、私人生活
- 当前正在做什么、想得到什么
- 能力、物品、实际权限
- 已有社会关系
- 重要经历与时间
- 他人如何评价他
- 与哪些世界内容存在稳定入口

示例关系：

```text
所属：[[木叶隐村]]
父亲：[[旗木朔茂]]
老师：[[波风水门]]
学生：[[漩涡鸣人]]
掌握：[[雷切]]
拥有：[[写轮眼]]
参与：[[神无毗桥之战]]
```

### 3.2 地点卡

建议关注：

- 地理位置、范围、环境、交通
- 里面有哪些组织、人物、资源、活动
- 谁控制、谁能进入、进入需要什么
- 日常怎样运行
- 通向哪里，物理/社会/信息通路分别是什么
- 有什么独有资源、危险、生活和高价内容

### 3.3 组织卡

建议关注：

- 组织真实形态与活动区域
- 领导、关键岗位、成员结构
- 财源、资产、技术、资源
- 决策、任命、继承和否决方式
- 当前目标、现行事务、内部派系
- 对外盟友、交易对象、敌手、监管者
- 实际能够做什么，以及做不到什么

### 3.4 能力 / 规则 / 技术卡

建议关注：

- 它是什么，为什么能成立
- 谁可以获得、学习、使用
- 实际能做哪些动作
- 生效对象、范围与边界
- 前置、反制、组合、传承
- 需要什么资源/环境/资格
- 在社会里为什么值钱
- 它怎样连接职业、组织、产业和更高阶地图

### 3.5 资源 / 物品 / 作品卡

建议关注：

- 在哪里、谁持有
- 为什么有价值
- 如何生产/取得/转让
- 实际能怎样使用
- 会不会耗尽、再生、升值
- 能换来什么
- 取得后是否长期归属
- 与哪些人物、组织、产业、事件连接

### 3.6 事件 / 活动卡

建议关注：

- 何时、何地、谁参与
- 事情为什么发生
- 各方已经采取什么行动
- 哪些资源、规则、关系正在起作用
- 结果改变了什么世界事实
- 对哪些人物/组织/地点留下长期影响

> 对 Source World，事件卡保存原著/历史/设定中的世界资料。小说正文实际改变世界后的动态结算仍进入 Project Reality，不把 Source World 变成运行态事件库。

## 4. Typed Relation Vocabulary｜世界内容的共同语法

关系词是**作者可读的世界语言**，不是复杂 Relationship Schema。

### 4.1 空间

- `位于 ↔ 包含`
- `通往 ↔ 通往`
- `邻接 ↔ 邻接`
- `控制 ↔ 被控制`
- `活动于 ↔ 活动者`

### 4.2 人与社会

- `所属 ↔ 成员`
- `任职 ↔ 任职者`
- `领导 ↔ 下属`
- `老师 ↔ 学生`
- `师父 ↔ 徒弟`
- `父亲/母亲/父母 ↔ 子女`
- `兄弟/姐妹/配偶/朋友/盟友/敌对/竞争/搭档` 为对称关系
- `效忠 ↔ 效忠者`
- `监管 ↔ 被监管`

### 4.3 力量与能力

- `掌握 ↔ 掌握者`
- `使用 ↔ 使用者`
- `传授 ↔ 受传者`
- `前置 ↔ 后续`
- `克制 ↔ 被克制`
- `反制 ↔ 被反制`
- `组合 ↔ 组合`
- `来源 ↔ 产出`

### 4.4 资产与经济

- `拥有 ↔ 拥有者`
- `生产 ↔ 生产者`
- `加工 ↔ 加工者`
- `运输 ↔ 运输者`
- `交易 ↔ 交易方`
- `消费 ↔ 消费者`
- `依赖 ↔ 支撑`
- `产于 ↔ 产出`

### 4.5 活动、历史与信息

- `参与 ↔ 参与者`
- `发生于 ↔ 发生事件`
- `导致 ↔ 结果来自`
- `涉及 ↔ 涉及`
- `知道 ↔ 被知晓`
- `来自 ↔ 信息来源`
- `传播到 ↔ 接收自`
- `评价 ↔ 被评价`

这是一份**可扩展词汇表**。未登记关系仍允许被解析和保存；登记只用于提供反向标签、编辑提示、筛选和统一显示，不应把自由卡片写作变成关系规则审计。

## 5. 七版研究怎样进入 Atlas，而不把 Atlas 做坏

| 研究内容                           | Atlas 是否保存                                                                        | 怎样保存                                             |
| ---------------------------------- | ------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| 地图、人物、组织、能力、资源、事件 | 是                                                                                    | 独立卡片 + typed links                               |
| 四张地图                           | 是                                                                                    | 同一地点/组织卡之间用不同关系形成不同视图            |
| 产业链                             | 是                                                                                    | 人物/组织/地点/资源之间的生产、加工、运输、交易边    |
| 超凡规则、境界、技能               | 是                                                                                    | rule / ability / resource 卡与关系                   |
| 男主个人 Build                     | Source World 只保存原著人物/参考角色既有 Build；小说男主动态 Build 属 Project Reality | 卡片参考 + 项目事实                                  |
| Affordance / 探索                  | 保存“世界对象真实允许什么、入口是什么”的资料；不做点击式游戏动作表                    | 正文 + 入口/通路/前置关系                            |
| 人物认知、社会评价                 | 原著/历史中稳定资料可写；正文后的动态变化归 Project Reality                           | 正文/信息卡/关系；不做全局好感值                     |
| Player Agency / GM                 | 否，不是世界实体                                                                      | 查询 Atlas 后临时推理                                |
| GOAP                               | 不强制字段化                                                                          | 人物卡保存目标、资源、认知和现实处境，运行时推理行动 |
| Storylets                          | 不作为 Source World 必填结构                                                          | 世界状态满足条件时由创作/运行层发现                  |
| AI Director / Reader Time          | 否                                                                                    | Novel Studio / 创作层                                |
| Living World 动态结算              | Source World 保存母体历史；小说改变后的状态归 Project Reality                         | 明确分层                                             |

```text

        ↓
World Content Framework
        ↓
┌────────────────────┬────────────────────────┐
│ Card Type Registry │ Typed Relation Vocabulary │
└────────────────────┴────────────────────────┘
```

## 7. 同一个框架服务两种世界来源

```text
已有母体世界资料                 第一模块生成的新世界
火影 / 海贼 / 历史 / 年代        原创玄幻 / 仙侠 / 都市……
          │                           │
          └──────────┬────────────────┘
                     ▼
                WORLD ATLAS
                     │
         World Content Framework
                     │
       Cards + Typed Relations + Index
```

第一模块负责**创造内容**，第二模块负责**承载、编辑、连接、查询内容**。

二者共享同一套世界语言，但职责绝不混合。

## 8. 防止再次走偏

以后面对 v0.1～v0.7 中的任一概念，按以下状态机判断：

```text
【这个概念是什么？】
       │
       ├─ 世界里有稳定身份的对象？
       │       └─ 是 → Card Type / 一张卡
       │
       ├─ 两个世界对象之间的稳定语义？
       │       └─ 是 → typed relation
       │
       ├─ 一张卡值得长期阅读的内容维度？
       │       └─ 是 → template hint / 正文
       │
       ├─ 多张卡连起来才能看见的结构？
       │       └─ 是 → graph / filter / derived view
       │
       └─ 故事运行、行动裁定、Reader调度？
               └─ 是 → 不字段化，归 Project Reality / Novel Studio / 运行推理
```

**任何新 SQL / 新强制字段提议，都必须先通过这张状态机。**

如果自由卡片 + typed links + 派生视图已经能够表达，就不要为了“理论完整”增加数据库复杂度。
