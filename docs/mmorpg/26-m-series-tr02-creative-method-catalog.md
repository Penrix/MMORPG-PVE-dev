# 2. M01A｜六问可玩性搜索

## 2.1 它真正解决什么

当世界已经有很多具体对象，但模型只会说：

```text
发生冲突
→ 男主解决
→ 众人震惊
→ 获得奖励
```

M01A 不先套剧情模板，而是问：

> **现有的人、事、物、能力、规则和关系，还能产生什么原来没有的新作用？**

## 2.2 六个母问题

### Q1｜当前有什么东西值得玩？

不是列设定，而是找：

- 哪个人已经具备发动事情的欲望与筹码；
- 哪件资源有特殊用途；
- 哪种能力可以作用到新的对象；
- 哪段关系已经有重新定价的条件；
- 哪个组织、地点、规则、身份存在可利用的特殊性。

### Q2｜它们之间可以发生什么新作用？

把对象互相碰：

```text
人物 × 人物
人物 × 资源
能力 × 社会规则
旧资产 × 新地图
身份 × 他人认知
欲望 × 关系
```

重点不是“相遇”，而是接触以后**双方的可选动作发生什么变化**。

### Q3｜这个男主会选择怎么玩？

同一个机会，不同男主应该看到不同东西。

依据 P_A、欲望排序、具体 T、惯用手段判断：

- 他先看钱？
- 看女人？
- 看身份？
- 看高手？
- 看可以装逼的舞台？
- 看能滚出下一笔资产的入口？

### Q4｜别人会怎样主动回应？

恢复对方自己的：

- 欲望；
- 认知；
- 资源；
- 权限；
- 关系；
- 手段。

问他会拒绝、误判、试探、合作、讨价、争抢、利用、加注还是报复。

### Q5｜哪一种可能性最值得 Reader 消费？

比较的不是“最现实”，而是：

- 哪个最显男主魅力；
- 哪个让男主得到更贵的东西；
- 哪个更好笑、更风流、更得意、更刺激；
- 哪个能让旧资产一鱼多吃；
- 哪个真的值得 Reader 亲眼看。

### Q6｜这次行动还能长出什么？

看它留下：

- 人；
- 钱；
- 权限；
- 作品；
- 关系；
- 敌意；
- 承诺；
- 资格；
- 新误判；
- 新入口。

从而给后面继续供戏。

## 2.3 不是六格表

六问是**六个观察方向**。可以从 Q2 开始，也可以围绕 Q4 反推 Q1；不要求每次机械输出六段。

## 2.4 假执行

- 把现有名词重新列一遍；
- 用“发生冲突、展示实力”替代新作用；
- 所有人只围着男主反应，没有自己的下一手；
- 六问全部填满，却一个具体新动作都没有。

# 3. M01B｜三意识深层搜索

> **PLACEMENT: MODULE 3 EMBEDDED / ALWAYS ON.** M01B 不进入 `CreativeMethodInvocation`，也不等待 Router 选择。讲师 Story Director 每次做 Story Search、Stake / Story Node 设计、Payoff 与 Settlement 时，都同时读取升级、人物自己找事、Reader张力三个前线。

M01B 与 M01A 平行，不是它的检查表。

## 3.1 升级意识

不是问“怎么升级”，而是寻找：

```text
S0 当前真实位置
→
S1 Reader真正认作变贵的新位置
```

可以是：

- 能力；
- 身份；
- 财富；
- 权限；
- 作品；
- 圈层准入；
- 女人关系；
- 组织位置；
- 私人享受。

继续问：

- 大格之间有没有被一句话跳过的有价中间格；
- S1怎样让 Reader 看见；
- 取得 S1 后解锁什么新的对象和玩法。

## 3.2 找事意识 / 人物因果

寻找**高因果人物**：

```text
他本来就想做什么
+ 手里有什么
+ 为什么偏偏现在行动
→
与男主发生机会 / 邀约 / 利用 / 求助 / 竞争 / 麻烦
```

男主也可以主动找到对方并搅动其既有生活。

## 3.3 张力意识

问 Reader 真正要看哪一拍：

- 谁知道什么；
- 谁误判什么；
- 谁隐瞒什么；
- 哪一格结果最想看；
- 哪句话/动作/试探在改变关系；
- 当前兑现什么；
- 下一笔期待怎样继续立价。

悬念、好奇、惊奇是工具，不要求凑齐。

## 3.4 回返

```text
升级
→ 人物行动
→ Reader观看
→ 兑现
→ Reality改变 / 新解锁
↺
```

可以反过来：

- 先发现一个高价人物，再发现升级轴；
- 先想到一个精彩场面，再补人物因果；
- 新兑现重新改变下一轮搜索空间。

## 3.5 假执行

- 把升级写成数值+1；
- 临时生一个反派来“找事”；
- 张力只剩“Reader期待男主成功”；
- 把三意识变成固定三步剧情流水线。

# 4. M02｜六条思维链

M02 的核心不是六种内容分类，而是**六种搜索运动**。

## 4.1 星型

**动作：把一个问题炸向根本不同的方向。**

从不同：

- 对象；
- 用途；
- 欲望；
- 关系；
- 权力位置；
- 收益；
- 社会接口；

产生不同“牌”。

失败形状：列十个同类打脸、同类维修、同类赚钱。

## 4.2 网状

**动作：寻找两张高价牌之间真正贵的接口。**

不是：

```text
A遇见B
A和B合作
```

而是：

```text
A最贵的性质
×
B最贵的性质
→
哪一句具体关系能咬上？
→
A因为B多了什么新用途？
B因为A多了什么新价值？
是否长出第三样东西？
```

双方都涨价才是强接口。

## 4.3 树型

**动作：沿一条已经贵的方向，通过改变承重条件继续分叉。**

例如改变：

- 时机；
- 谁先动手；
- 利益分配；
- 对方身份；
- 可用资源；
- 是否公开；
- 是否已有旧关系。

每改一个真正承重条件，应该生出机制不同的行动和后果。

失败形状：把“准备→执行→成功”画成一棵假树。

## 4.4 对立

**动作：明确反转一个默认预设，再追它造成的真实连锁变化。**

可反转：

- 谁求谁；
- 谁拥有定价权；
- 谁保护谁；
- 谁利用谁；
- 谁公开谁隐藏；
- 利益流向；
- 身份高低；
- 物件用途；
- 角色默认欲望。

不是为了反转而反转，必须让具体人物因此换动机、筹码、行为和局面。

## 4.5 维度交叉

**动作：把一个已经成立的玩法/具体 T/社会手段，撞到另一种性质不同的世界维度。**

例如：

```text
旧玩法
× 新行业
× 新制度
× 新关系
× 新地图生态位
× 新力量规则
```

观察原玩法的：

- 用途；
- 门槛；
- 价格；
- 风险；
- 人物回应；

怎样改变。

失败形状：“经营+忍术”“才华+财阀”两个名词并排，机制没变。

## 4.6 链式

**动作：让已经发生的一手真正产生下一手。**

```text
A因自己的目标采取行动
→
B根据自己知道的事实和欲望回应
→
新状态 S1
→
A/B 的可选动作改变
→
下一手
→ ...
```

不预设链长，不先锁结局。

失败形状：先决定男主必赢，再让 NPC 一路降智配合。

## 4.7 六链的使用关系

```text
首次开放问题
  └─ 常可星型开枝
        ↓
发现两张贵牌
  └─ 可网状找接口

选中一枝
  └─ 树型深挖

思路僵死
  └─ 对立打破惯性

旧玩法进入新世界
  └─ 维度交叉

已经出现人物新行动
  └─ 链式继续

任何位置都可回返 / 换链 / 重复同一链
```

不是六步法。

# 5. M03｜TR02 三战略 × 五锚点 N 案快搜

## 5.1 现在的 M03 算法身份

当前 `database/m03` 是 Module 2 Creative Material Space。

与此同时，**现行第四代仍有一个叫 M03 的创作方法**：TR-I-02 五锚点 N 案战略组合。二者有历史血缘，但运行时不能混成一件东西。

## 5.2 它解决什么

新书/新方案早期，需要快速拉开 N 个**底层赢法不同**的候选，不要在第一个方案上过早投入人物、历史、具体剧情细化。

## 5.3 三战略是 AND，不是三种方案风格

每一案都同时检查：

1. **市场接受度**：目标 Reader 是否已有成熟认知和消费基础；
2. **AI 生产效率**：是否有成熟作品、具体故事、关系、职业运作、反复局面可借鉴；
3. **可持续爽感**：GF/玩法能否换对象反复兑现，并留下资产/关系/期待供下一轮。

缺一就回搜。

## 5.4 五锚点

同一题材/IP下，N案主要用四组差异锚点加题材锚点拉开：

```text
Genre / IP
+
RULE 世界特殊规则
+
GF 非对称优势
+
CP 起势 → 过程 → 高潮
+
END / GOAL / SCALE 远端人生与规模
```

每案必须说清：

> **主角靠什么赢，赢到什么。**

它的价值是**快速战略分叉**，不是完整故事。

## 5.5 深化阶段只是按需坐标

旧 21 槽不是固定表：

- 世界链：高价对象 / SUPPLY；
- 主角链：身份 / 前史 / 年龄 / 时间 / 起始资源；
- 成长链：阶段欲望 / OS+SIT/MOVE/T / ROAD+GATE / GF边界；
- 关系链：竞争者 / 关系发动机 / 关系网 / 演出单位 / 叙事格局。

只有需要深入某案才打开。

## 5.6 假执行

- 五锚点直接当完整故事；
- N案只换职业/皮肤，底层赢法相同；
- 三战略分别分给 A/B/C；
- 为了完整把 21 槽一次填满；
- 把 M03 素材库里的每张卡当作一个 M03 算法。

# 6. M03 历史有效方法｜SELECT / COMPOSE / VERIFY

这是旧 M03 形成史里仍有独立价值的**按需素材调用法**。

## SELECT｜查什么成熟东西值得拿来用

围绕当前真实问题，从可回读的素材库里选少量相容组件。

必须知道：

- 来源版本；
- 组件类别；
- 原编号/名称；
- 原义；
- 本轮要作用的具体对象；
- 为什么此时有价值；
- 容易怎样误用。

没有合适的就返回没有，不硬塞。

## COMPOSE｜让成熟组件真正进入当前故事对象

不是贴码。

最小生产关系：

```text
具体高价对象 X
+
男主实际手段 R
+
成熟组件提供的特殊机制
+
另一人物自己的利益和回应
→
Reader可见兑现 Y
→
留下可再用的资产/关系/新问题
```

不同候选要机制不同，不是换人名。

## VERIFY｜验它到底有没有真的演出来

检查：

- 组件出处是否真实；
- 套路是否在人物行动和 Reader 可见过程中兑现；
- P_A 是否真会这样做；
- Story Concept 有没有被偷换；
- 是否形成独特且可继续玩的局面；
- Candidate / Plan / Reality 有没有混写。

返回 PASS / PARTIAL / FAIL 和最小修正。

## 当前身份

SELECT / COMPOSE / VERIFY **不是 M03 五锚点快搜的必经三关**。需要素材检索、适配、验货时单独调用。

# 7. M04｜成熟故事原型复入 × 当前世界重写人物因果

## 7.1 为什么有它

只有：

```text
GF
+ CP
+ OS
+ Road
```

经常只会生出：

> 男主展示才华 → 大人物震惊 → 美女欣赏 → 男主成功。

M04 主动调用模型已经知道的**成熟故事原型**，不是只调用套路标签。

## 7.2 核心动作

### A. 找成熟人物因果

不是只说《大鼻子情圣》，而要恢复：

```text
谁想要什么
谁掌握什么
谁借谁的能力/身份
谁误认了谁
谁因此主动采取第二手
故事怎样转向与结算
```

可以来自单一作品，也可以明确标为“多源综合成熟原型”。

### B. 三战略共同筛选

仍用 TR02：

- Reader 是否愿意消费；
- 是否有足够可行动的成熟样本供继续生产；
- 一次事件能否留下下一场的关系/资产/期待。

### C. 关系与结算重配

把原型迁到 B 时：

- 保留真正好看的因果；
- 更换人物、世界价格和准入；
- 重新分配男主主动权；
- 让 GF 真正进入具体手段；
- 让其他人有自己的目标；
- 改写收益归属；
- 男主平仓盈利；
- 留下下一次真实资产。

### D. 再做 TR02 七项映射

Genre / Role / GF / OS / CP / TF / SF 是**记录和校准**，不负责凭标签自动生成故事。

## 7.3 假执行

- “身份错位”四个字冒充成熟故事；
- 只搬名场面，不知道人物为什么行动；
- 换名字后仍按原作完整事件走；
- 悲剧原型换皮以后男主仍净亏；
- 只有一次好桥段，却宣称有整书 Story Engine。

# 8. M05｜PLAY 反差与新鲜感增补

## 8.1 它只在已有方案成立后工作

M05 不重选：

- RULE；
- GF；
- CP；
- OS；
- END / GOAL / SCALE；
- Story Concept；
- 底层赢法。

它问：

> **同样的赢法，还能不能多一种可反复演、每次又不完全一样的操作机制？**

## 8.2 操作

1. 找原方案尚未利用的价差/落差：
   - 身份；
   - 知识；
   - 社会价格；
   - 规则；
   - 职业/私生活；
   - 关系；
   - 公开/隐藏。
2. 从真实 PLAY 库筛兼容项。
3. 先试演一次具体互动。
4. 改变一个有意义条件，再演第二次：
   - 换人物；
   - 换阶段；
   - 换公开度；
   - 换规模；
   - 换价值媒介。
5. 两次仍然有不同戏，才说明可复用。

## 8.3 假执行

- 借 PLAY 偷加新 GF；
- “大家低估男主→震惊”重复一百次；
- 只给一个“身份反差”标签；
- 原故事本来不成立，却靠 PLAY 强行补妆。

# 9. M06｜故事总谱 × 具体 T 长篇运行

M06 不是“再想一个下一段剧情”，而是看**已经活着的玩法、资产、人物线怎样跨 Story Time 继续运作。**

## 9.1 两类长期对象

### 具体 T

```text
对象 X
→ 男主稳定做法 R
→ 实际产物 Y
```

只有已经取得的 Y 才是下一只 T 的真实输入。

### Story Movement

商业、身份、女人、亲友、冒险、对抗、私人生活等线可以：

- 活跃；
- 潜伏；
- 预热；
- 休止；
- 交汇；
- 换到 Reader 前景；
- 重新启动。

Active 不等于下一章必须写。

## 9.2 九个独立操作

| 操作   | 搜什么                                               |
| ------ | ---------------------------------------------------- |
| **T1** | 当前到底有哪些可运行 T 和真实资源                    |
| **T2** | T1 的产物 Y 怎样被 T2 真正使用                       |
| **S1** | 哪些人物/故事运动仍在活着                            |
| **S2** | Reader 主奏是否该换挡，换到哪条具体线                |
| **O1** | 当前地图什么对象与某只 T 特别合拍                    |
| **O2** | 两条线通过什么具体人/物/地点自然交汇                 |
| **L1** | 人、资源、T 怎样跨区段继续存在                       |
| **W1** | 新事实发生后怎样更新供料和 Movement                  |
| **Q1** | 删除旧产物 Y，后面的戏是否仍然原样发生，以检验假因果 |

九项按问题选，不按顺序跑。

# 10. M07｜男主人格“果 → 因”重建

## 10.1 保留的不是标签

目标不是：

```text
康剑飞
→ 胆大、好色、聪明
→ 换一个东京导演
```

而是从 A 正文恢复：

- 他在什么利益现场怎样做；
- 真正想要什么；
- 怎样说话改变别人；
- 怎样使用自己的本事；
- 利用人时是什么姿态；
- 亲密关系里怎么行动；
- 哪些边界会让他换手段。

形成**能够预测下一手**的最小人物母型。

## 10.2 果→因

再问：

> B 世界中怎样一套**不同的人生经历、家庭、组织、旧关系、本事和成功失败史**，可以自然养出这种行为结果？

不能一条童年创伤解释全部人格。

## 10.3 盲场景测试

把 B 新人物丢到至少两个性质不同的陌生情境：

- 权势人物；
- 女人；
- 利益冲突；
- 兄弟需求；
- 成功享受；
- 失手。

看他能否自己做出有辨识度的选择。

失败就回行为母型或形成史，不继续加性格形容词。

# 11. M08｜成功旧书 Story Concept × Story Engine 双轨迁移

## 11.1 两样东西不能混

### Story Concept

这本书长期让 Reader 看：

- 哪种男人；
- 什么人生；
- 哪些关系；
- 什么社会位置；
- 什么特殊趣味。

### Story Engine

这本书为什么可以长期不断有戏：

- 哪些成熟流派打法；
- 哪些具体 T；
- 什么行动→取得；
- 什么人物/作品/行业/关系反复供料；
- 上一次所得怎样打开下一次。

## 11.2 两阶段

```text
A 原著
├─ 恢复 A-Concept
└─ 恢复 A-Engine
        ↓
分别迁移到 B
├─ B中怎样继续卖这种男人生活
└─ B中怎样继续用成熟玩法供戏
        ↓
互相校准
```

只剩 Concept = 宣言。

只剩 Engine = 技术堆。

两者都像 A、但 B 社会不存在 = 换皮。

## 11.3 假执行

- 用“文抄公+风流”代替整书 Concept；
- 用几个流派标签代替 Engine；
- A→B 只换时间、职业、城市和女人名字；
- 直接搬 A 的卷章事件顺序。

# 12. M09｜Reader 情绪乐句 → 演奏语义 → B 新戏

## 12.1 它解决的是“因果能写通，但不好玩”

M09 从成功 A 的真实 Reader Time 中提取：

```text
这一拍 Reader 到底吃到了什么？
是什么具体表演让它成立？
```

然后把它转译成模型熟悉的成熟演奏语言，例如：

- 民俗恐怖 → 隐藏高人镇场；
- 双人漫才；
- 生活流捡漏 + 反恐怖喜剧；
- 身份错位无形装逼；
- 恋爱关系试探；
- 旁人反应式装逼；
- 治愈系搭档养成。

## 12.2 每个“乐句”保留

- A 可回听的真实场景；
- Reader 这一拍具体消费；
- 成熟演法语义；
- 一句短导演指令；
- A 哪些独有物件/人物/事件不能搬。

## 12.3 再进入 B

用：

```text
B当前具体对象
+ P_A
+ Reality
+ 选中的演奏语义
→
搜索新的B人物行动与Reader观看过程
```

不是把 A 事件换皮。

## 12.4 三者分权

```text
P_A
= 这个男人是谁、怎样活

演奏状态
= 这一场想让 Reader 吃什么感觉

M02六链
= 搜索怎样移动
```

三者不能互相替代。

# 13. M10｜多圈人物动力 × 三个 Why × A/B 选角

M10 解决：

> A 书里为什么偏偏是这个人？换到 B 世界以后，为什么应该是另一个具体人，而不是“功能相同的人”？

## 13.1 先恢复圈子，不先配功能位

A 中：

- 报业圈；
- 军政圈；
- 文学圈；
- 贵族/宫廷；
- 戏剧；
- 朋友；
- 女人；
- 家庭……

每个圈有自己的事务，人物在男主没出现时也有自己的欲望和行动。

## 13.2 人物真正的生成单位

```text
欲望
+ 当前触发
+ 障碍
+ 可用资源/权限
+ 惯常策略
+ 关系历史
→
特殊行动
→
别人回应
→
圈内与跨圈后果
```

不是“这个人有军权，所以在法国找一个有军权的人”。

## 13.3 三个 Why 必须拆开

### Why-A-casting

为什么 A 的作者在这个阶段用这个人/这个圈，而不是 A 世界里另一个实际可用候选？

回答 Reader 价格、关系反差、后续资产。

### Why-A-character

这个 A 人物自己为什么今天这样做？

回答其意图、触发、策略和回应。

### Why-B-choice

B 世界里为什么选这个具体人，而不是另外几个看起来也匹配的人？

回答其当时欲望、现实权限、关系、策略、Reader识别价值与后续圈子。

## 13.4 历史地图分层

- **H1**：真实知名/高价人物，以及可考的重要职位占有人，尊重真实身份与旧关系；
- **H2**：时代制度和机构运行锚点；
- **F**：真正无历史承重身份的普通人物，可积极创造；
- **T**：历史已有关系与小说新增关系按时间分开。

## 13.5 A→B 真正替换单位

```text
圈子
+ 独立事务
+ 人物关系
+ 意图-障碍-策略-后果
+ Reader情绪
+ 长篇资产
```

不是职业名、官衔、社会地位或单一功能。

# 14. TR-I-02 版本谱系：每一版到底增加了什么“想法运动”

这里不按“版本号越高越正确”处理。

TR-I-02 是多年演化出来的**方法来源树**。不同版本保留了不同有价值的搜索运动；同时混有当时的用户偏好、题材政策、市场判断和输出模板。后两者不能一律升格为通用算法。

## 14.1 v1.0 / v1.1 Concept Matrix｜矩阵组合

最初核心：

```text
题材
× GF
× 人设
× 开局
→
寻找组合后的“化学反应”
→
多个微型提案
```

关键不是随机拼标签，而是问：

> 为什么 A 与 B 放在一起会产生一种原本不存在的新玩法？

**留下的方法：MATRIX_COMBINE。**

---

## 14.2 v2.0 偏好解码｜用户选择样本加权

在市场元素外加入：

```text
用户喜欢过什么
用户明确排除什么
→
反推高权重偏好
→
在矩阵组合时加权
```

**留下的方法：PREFERENCE_WEIGHTING。**

不是永久锁死一次旧偏好，最新作者裁决始终优先。

---

## 14.3 “初始版·更随机”｜强制映射再融合

把创意明确拆成：

```text
从组件库为各类别选积木
→
公开映射清单
→
融合生成
→
检查
```

价值在于可追踪“这个方案究竟由什么组成”。

**留下的方法：EXPLICIT_COMPONENT_MAPPING。**

但“每个类别必须选一个”只是该版生产约束，不是今天所有任务的必填义务。

---

## 14.4 中观公式 v1.0 / v1.1｜公式锁定与层级选择

思路：

```text
先选成功的中观公式/组合基座
→
再填具体职业、GF、开局、人设
→
熔炼核心概念
```

它更像：

> **先定一个成熟中层结构，再向下寻找具体实现。**

**留下的方法：MESO_FORMULA_LOCK。**

其中“TR-I-01 唯一元素库”“统一人设模型绝对 VETO”等是时期政策，不自动进入当前通用算法。

---

## 14.5 微观元素矩阵 v1.2｜中观 → 微观分解

它把：

```text
职业 / 题材
→ 中观GF公式
→ 微观具体形态
→ 爽点/冲突
→ 开局
→ 人设外显
```

逐层往下找。

例如不是停在“职业技能面板”，而是继续问：

- 面板显示什么；
- 任务作用什么；
- 熟练度怎样涨；
- 哪种未来资料进入；
- 这些微观形态怎样与职业发生特殊关系。

**留下的方法：MICRO_RESOLUTION。**

---

## 14.6 微观元素矩阵 v1.3｜开放式数据库加权检索

这是 TR02 演化中非常重要的一步：

```text
已有报告 / Curated DB
→ 提供高权重方向
→ 不封死搜索
→ 继续到模型已有知识中的影视/小说/游戏/现实案例做开放检索
→
A. 库内优化
B. 库外创新
C. 跨界组合
```

这里已经明确：

> **人工素材库是高质量搜索空间和权重，不是模型联想的牢笼。**

**留下两个方法：WEIGHTED_RETRIEVAL + OPEN_ASSOCIATION_RECALL。**

---

## 14.7 v2.1 题材内深耕｜固定主板，热插板卡

核心比喻：

```text
世界 / 题材 = 主板
身份 / GF / 开局 / 冲突 = 可热插拔板卡
```

先锁当前赛道边界，再在内部寻找变化。

四步：

1. 解构与映射；
2. 锚定核心驱动；
3. 热插拔融合；
4. 检查是否把题材写跑。

**留下的方法：GENRE_DEEP_DIVE + HOT_SWAP。**

“世界永远不能扩展”是该版针对题材欺诈的时期约束，不是所有玄幻/同人的通用真理。

---

## 14.8 v2.3 策略驱动｜反惰性 vs 爆款热插拔

这一版把两种完全不同的搜索动作明确分开。

### Strategy A｜反惰性组合

禁止把某个组件放回它最熟悉的“原配”。

```text
成熟GF / 玩法
→
故意寻找不同职业、时代、阶层、世界接口
→
重新解释为什么它在那里成立
```

目标：打破模型第一先验。

**留下的方法：ANTI_INERTIA_CROSS_DOMAIN。**

### Strategy B｜爆款基因热插拔

保留一个经过验证的强基座：

```text
成熟 GF + 身份 / 核心玩法
```

只替换：

- 开局困境；
- 核心矛盾；
- 世界细节；
- 某一承重变量。

目标：在熟悉与新鲜之间控制变化幅度。

**留下的方法：HOT_SWAP_BASELINE。**

两者不是好坏关系，是两个不同搜索旋钮。

## 14.9 v2.4 / v2.6｜稳定世界下的规模扩张 + 一句话压缩

这一支纠正“长篇=中途换世界规则”。

关注：

```text
规模
层级
资本
地理范围
产业链
关系网
权限
```

怎样逐步升价。

**留下的方法：SCALE_EXPANSION_TEST。**

v2.6 还把一句话项目压缩成三个观察点：

- 核心冲突；
- 人物张力；
- 悬念钩子。

**留下的方法：ONE_SENTENCE_COMPRESSION。**

它是候选表达/检查工具，不是 Story Director。

## 14.10 v3.0 主题深潜｜先理解赛道，再组合

在组合之前，先扫描五维：

1. 核心规则 / 力量体系；
2. 社会结构；
3. 核心矛盾；
4. 关键势力；
5. 时代 / 氛围。

作用：

> 把搜索空间先变成“这个赛道真正有什么”，再去选组件，降低错位组合。

**留下的方法：THEME_5D_SCAN。**

## 14.11 v3.4｜审美 DNA 加权矩阵

不是只找“市场最热”，而是：

```text
候选组件
×
作者长期审美
×
本轮明确偏好/排除
→
重新加权
```

**留下的方法：AESTHETIC_WEIGHTED_MATRIX。**

该版具体“征服模板”“IP偏好”等属于历史 profile，不作为今天通用算法本体。

## 14.12 v3.5 R.E.M.A.K.E / v3.6 Diamond-Class｜猎场、非对称优势、冲突战利品

这一代做成过巨型系统，其中很多是时期性硬规则，但有几种搜索镜头仍有价值。

### CONFLICT_LOOT_LENS

把一个男频动作问成：

```text
克服什么阻力
→
靠什么手段赢
→
真正拿走什么
→
这份战利品下一次值多少钱
```

### CONFLICT_INTENSITY_SCALING

同一个“战斗”按题材改变表现：

- 玄幻可能是肉体消灭；
- 商战可能是资产/控制权；
- 文娱可能是排名、资源、话语权；
- 日常可能是关系、待遇、选择权。

这是表现尺度旋钮，不是要求所有题材天天打架。

### ASYMMETRIC_ADVANTAGE

围绕“不公平优势”找：

- 信息；
- 规则；
- 速度；
- 资源；
- 身份；
- 特殊体系；
- 错位赛道。

并问它怎样重复产生结果、怎样继续升价。

### HUNTING_GROUND_SCAN

十维扫描“这张世界有什么可以下手”：

- 时机；
- 靶子；
- 资产；
- 生态位；
- 介入点；
- 风险；
- 爽感放大；
- 原有剧情惯性；
- 势力/人脉；
- 规则/定义权。

这些是搜索镜头。

### 历史限制

v3.5 / v3.6 中的：

- “书名必须作为唯一第一入口”；
- 固定高密度冲突频率；
- 所有题材统一征服终局；
- 某些当时的 IP / 人设禁项；

不能作为当前 M 层普遍铁律。

后续统一版已经主动修正其中多项。

## 14.13 v2.3-R 连载生存改进稿｜双引擎

这一版很有价值，因为它明确保留了**两种不同的候选生成性格**。

### Engine A｜矩阵稳定组

```text
赛道合同
+ 初始身份
+ 核心欲望
+ 非对称优势
+ 第一冲突
+ 主要收益
+ 可重复玩法循环
+ 长期扩张
→
稳健候选
```

**留下的方法：STABLE_MATRIX_GENERATION。**

### Engine B｜跳跃随机组

```text
星型发散
→ 树型归类/选择
→ 链式深挖
→ 连载验证
```

要求只保留一个真正高跳跃核心，避免五个奇点互相打架。

**留下的方法：JUMP_RANDOM_GENERATION。**

### Serialization Gates

候选再经：

- 用户兴趣；
- 一句话卖点；
- 男主行动；
- 黄金三章；
- 三万字；
- 十万字/上架；
- 长篇扩张；
- 生产风险。

**留下的方法：SERIAL_SURVIVAL_GATE。**

# 17. 方法与讲师 Story Director 的正确接缝

```text
23 / 讲师方法已经确定：
当前 Upgrade Stage
+ Existing Cast / Reality
+ 稀缺 / 固有认知 / 信息差
+ 三阵营 / Stake
→ 什么值得写、人物线与Payoff方向
                    │
                    ├─ 当前答案足够好
                    │      ↓
                    │   直接设计 Story Node
                    │
                    └─ 需要更多候选 / 新关系 / 新演法 / 成熟先验
                           ↓
                      选一个 M / TR02 方法
                           ↓
                      得到候选分支
                           ├─ 不值钱 → 换方法 / 回返
                           ├─ 撞 Reality → 换对象 / 退回
                           └─ 值钱 → Director采用或修改
                                      ↓
                               Stake / Story Node
                                      ↓
                              S06 / S07 / S08
```

**M 方法不拥有最终“值得写”的裁决权。**

它们负责让模型：

- 不停在第一个熟悉答案；
- 有办法打开不同方向；
- 有办法把成熟经验迁入当前对象；
- 有办法保留分叉和回返；
- 有办法产生机制不同的候选。

讲师方法负责把这些候选真正编成商业男频故事。

# 18. 当前工程缺口，按正确层级描述

本轮重新校正后，**不是缺一层 Creative Workbench，也不是“还不知道什么值得写”。**

当前真正缺的是：

> **M / TR02 方法知识虽然已经在 cognition 与 Drive 中存在，但 MMORPG Runtime 只有通用的 `CreativeMethodInvocation` 端口，还没有把这些方法的职责、调用条件、来源版本和互斥边界整理成一份可恢复的正式目录。**

本文先补的是**认知 Authority**。

因此本轮不急着做：

- 新 Story Director；
- 新 S 层；
- 新“创意工作台”；
- 新算法注册中心；
- 把 TR02 全版本合并成一个超级 Prompt；
- 把所有历史 policy 写进 Runtime。

后续若开始实现 M 方法运行时，应从本文选择**一个具体方法**做 adapter / executor，并用其真实文档做验收，而不是先设计一套万能算法框架。
