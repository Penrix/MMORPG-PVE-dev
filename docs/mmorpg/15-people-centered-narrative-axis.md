# 第二模块｜People-Centered Narrative Axis（2026-11-21，第二模块第一原则）

> **这是 World Atlas 在“世界内容框架”之上的叙事重心裁决。**
>
> [14：World Atlas 世界内容框架](14-world-atlas-content-framework-v01.md)回答“一个世界应该有什么”；本文回答“这些世界内容在小说中为什么不是平权地被使用，以及为什么【人】必须成为第二条叙事轴的中心”。
>
> 这项调整**不改变数据库物理结构**。它改变的是 Atlas 的浏览、查询、检索、图谱展开和 LLM Context 优先级。

---

## 0. 一句话原则

**十个 World Family 是内容分类轴；People-centered 是叙事关系轴。两条轴叠在同一批 Card + Typed Edge 上，不是二选一。**

```text
【内容分类轴：世界有什么】

People / Space / Organization / Power / Asset
Economy / Activity / Information / Value / Playable

                    │
                    │ 同一批卡片与关系
                    ▼

【叙事关系轴：故事从哪里发动】

                      PEOPLE
                        │
        ┌───────────────┼────────────────┐
        │               │                │
      人 ↔ 人          人的集合           人 ↔ 世界对象
        │               │                │
  亲属/师徒/敌友    组织/家族/阵营     拥有/掌握/控制/知道
  情感/合作/竞争    国家/公司/宗门     进入/参与/生产/交易
                                         │
                         ┌───────────────┼───────────────┐
                         ▼               ▼               ▼
                       地点            资源             能力
                       信息            物品             事件
                       制度            职位             技术
```

外围仍然存在真正非人的世界：

```text
地形 / 气候 / 自然规则 / 灾害 / 纯自然资源 / 无人格怪物
```

但在小说世界总数据量和故事发动机会中，它们通常不是主体。

---

## 1. 为什么十个 Family 仍然必须并排

十个 Family 解决的是**世界内容覆盖**。

如果只围绕人物建资料，会得到大量人物档案，却可能没有：

- 可进入的空间
- 可取得的资源
- 可学习的能力
- 可运行的组织
- 可生产/流通的产业
- 正在发生的活动
- 信息与认知差
- 社会价格
- 可争取、可享受、可改变的高价内容

所以：

> **People 是叙事中心，不等于 People 吞掉其他九类。**

World Family 继续并排，是为了检查“世界有没有缺内容”。

---

## 2. 为什么 People 又必须成为第二条中心轴

商业长篇真正发生的故事，大部分不是抽象对象直接与男主发生关系，而是**人通过对象彼此作用**。

### 2.1 组织是被结构化的人

一个组织真正能产生故事的，不只是组织说明，而是：

- 谁领导
- 谁真正掌权
- 谁负责某个入口
- 谁拥有任命/否决权
- 谁掌握资源
- 谁属于哪个派系
- 谁与谁合作、敌对、竞争

因此组织卡是重要节点，但组织的可玩性大量来自其内部和周围的人。

### 2.2 权力通常有人形接口

签约权、晋升权、贷款权、军队调动权、立项权、准入权，最终通常落在具体人物、职位和关系网络上。

男主进入更昂贵的社会空间，经常不是“满足抽象 Access Requirement”，而是：

> **找到一个能打开门的人。**

### 2.3 资产和能力通常也被人占有、垄断、教授、争夺

宝物、技术、作品、土地、秘密、能力、资源，大量都存在：

- 谁拥有
- 谁知道
- 谁保管
- 谁能教
- 谁能鉴定
- 谁想抢
- 谁能卖
- 谁能阻止别人取得

即使是无主宝物，也常通过守护者、竞争者、发现者、地图持有人、探索者重新接入人物网络。

### 2.4 地点只有装入人，才从“地图”变成“场域”

木叶医院、报社、银行、军营、宗门大殿，不只需要地点说明，更需要：

- 谁常驻
- 谁负责
- 谁能带人进入
- 谁控制关键资源
- 谁正在这里做事
- 谁与谁存在冲突或利益

因此一个小说地点真正可用时，通常是一处**有人在生活和行动的社会空间**。

---

## 3. 为什么这不需要修改数据库 Schema

当前底层本来就是：

```text
SilverBullet 思想
→ 完整 Markdown 卡片是资料真相

Breadcrumbs 思想
→ 卡片之间存在有语义的 typed relations

Relations 思想
→ 任意卡片都可以成为关系图中心
```

物理数据仍然只是：

```text
Card / Node
+
Typed Relation / Edge
```

例如：

```text
卡卡西      character
木叶        organization
雷切        ability
神无毗桥    event

卡卡西 ─所属→ 木叶
卡卡西 ─掌握→ 雷切
卡卡西 ─参与→ 神无毗桥
卡卡西 ─老师→ 水门
```

这份数据既可以按 World Family 浏览，也可以以人物为中心浏览。

因此：

> **People-centered 是 View / Query / Priority，不是新的 Database Schema。**

禁止因为“人是中心”而重新设计一套 People 根表、人物专用关系数据库或层级树。

---

## 4. 三个底座为什么恰好适合这个理念

| 底座思想         | 表面能力         | 对 People-centered World Atlas 的真正作用                              |
| ---------------- | ---------------- | ---------------------------------------------------------------------- |
| **SilverBullet** | Markdown + Index | 让一个“人”保持完整、复杂、可长期生长，不被几十个固定字段阉割           |
| **Breadcrumbs**  | Typed Relations  | 把“人与人、人与组织、人与资源、人与能力、人与地点”变成可查询的语义关系 |
| **Relations**    | Graph UI         | 让作者和 LLM 从任意人物出发，展开其所在的完整社会世界                  |

可以简化为：

```text
SilverBullet
负责：这个人是谁

Breadcrumbs
负责：这个人与谁、与什么有什么关系

Relations
负责：这些人和关系怎样组成一个世界
```

---

## 5. 工程上真正需要改变什么

数据库不改，但默认行为需要倾斜。

| 层              | 调整                                                                 |
| --------------- | -------------------------------------------------------------------- |
| Card Storage    | 不变，仍是自由 Markdown + 少量稳定元数据                             |
| Card Types      | 不变，十个 Family 继续覆盖完整世界                                   |
| Typed Relations | 不变，继续允许任意卡之间建立有语义关系                               |
| Graph UI        | 任意节点都能做中心；**非人物卡展开关系时，人物节点优先出现**         |
| Retrieval       | 查询地点、组织、资源、能力、事件时，优先把与其直接相关的人带回来     |
| LLM Context     | 不只给对象说明，优先附带“谁拥有/控制/知道/活动于/参与/阻碍/提供入口” |
| World Audit     | 除了检查十 Family 覆盖，还检查高价值非人物内容是否接上具体人物       |
| Templates       | 非人物卡继续主动提示“谁拥有、谁控制、谁参与、谁能带入、谁在这里行动” |

这不是让所有查询都强行返回人物，而是给**小说叙事相关查询**一个默认优先级。

---

## 6. 默认关系展开顺序

当一张非人物卡有大量邻接节点时，默认优先级应是：

```text
具体人物
   ↓
组织 / 职位 / 人的集合
   ↓
地点 / 资源 / 物品 / 能力 / 信息 / 事件
   ↓
规则 / 技术 / 其他外围对象
```

原因不是“人物类型在数据库里更高级”，而是：

> **小说下一步最常需要回答的是：我会遇到谁？谁能帮我？谁会挡我？谁控制这个东西？**

用户仍然可以按关系类型、Card Type 或 World Family 切换视图。

---

## 7. 非人物卡的最小人物连接检查

这不是强制字段，也不是保存校验，只是作者/LLM 的世界完整性提示。

```text
Location
→ 谁住在这里？
→ 谁控制这里？
→ 谁能带人进入？
→ 谁正在这里行动？

Organization
→ 谁领导？
→ 谁真正掌权？
→ 谁是关键成员？
→ 谁能提供入口或阻碍？

Asset / Resource
→ 谁拥有？
→ 谁生产？
→ 谁需要？
→ 谁在争夺？

Ability / Technology
→ 谁掌握？
→ 谁能教？
→ 谁垄断？
→ 谁能反制？

Information
→ 谁知道？
→ 谁不知道？
→ 谁在隐瞒？
→ 谁想知道？

Event / Activity
→ 谁发动？
→ 谁参与？
→ 谁受益？
→ 谁受损？
```

如果答案确实是“没有任何人”，那它可以作为真正非人的环境内容存在，不为了原则硬造 NPC。

## 8. 防重犯状态机

```text
【发现 People 是叙事中心】
          │
          ├─ 要不要改 SQL / 把 People 设为数据库根节点？
          │          └─ 不要
          │
          ├─ 十个 World Family 要不要取消平权分类？
          │          └─ 不要
          │
          ├─ 那改什么？
          │          ├─ 默认 Graph 展开
          │          ├─ Retrieval 优先级
          │          ├─ LLM Context 组装
          │          ├─ Template hints
          │          └─ World completeness audit
          │
          └─ 数据仍是什么？
                     └─ 同一批 Card + Typed Edge
```

## 9. 当前裁决

**World Atlas 同时拥有两条正交轴：**

1. **World Content Axis**：十个 World Family 并排，保证世界完整。
2. **People-Centered Narrative Axis**：人物作为小说故事最主要的发动节点，决定关系图展开、检索和上下文优先级。

这两条轴共同建立在同一套：

**SilverBullet 的卡片/索引思想 + Breadcrumbs 的类型关系 + Relations 的图谱 UI**

之上。

任何后续实现如果把“People-centered”误解成重新改数据库层级，或把“十 Family 并排”误解成所有内容在小说叙事中必须同权，都属于走偏。
