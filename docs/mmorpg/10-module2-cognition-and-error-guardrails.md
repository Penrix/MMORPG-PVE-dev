## 0. 不可再误解的总架构

```text
多个原生母体（Reference：火影、海贼、美漫、某朝代、某时代……）
  ├─ 原著/历史全量资料、前后时代、完整人物关系和世界规则
  ├─ 每个事实的出处、版本、证据和价值背景
  └─ 各自的原生材料不因项目的故事改写而改变
                      ↓ 选择、引用、对应（不是无审查复制成已发生）
一本小说 PROJECT
  ├─ 作者意图、故事设定集、世界资料、正文（复用 NarraLume 原生能力）
  ├─ 唯一项目 Reality / Canon：同一个主角持续生活的真实历史
  ├─ 可有多个宇宙/世界区、历史阶段、时间分支、跨世界关系
  ├─ 跨世界/时间旅行只是项目内部的一类真实事件，不是创建项目
  ├─ 角色具有稳定的项目身份，位置、资产、技能和知识随事件变化
  └─ Story Writeback → 仅写本项目已真正发生的现实
```

**一个 Project Reality ≠ 一个原作母体 ≠ 一个宇宙 ≠ 一张地图 ≠ 一条时间线。**

### 三个必须通过的具体试验

1. **火影 → 海贼 → 返回火影**：一个小说项目绑定火影、海贼两个以上原生资料母体；男主只有一个持续项目身份；人物及其取得的真实能力、资产、记忆和关系不重置。回到火影可以继续沿既有事实和变化写，两个源母体自身不被修改。
2. **火影内部楼兰龙脉穿越时间**：同一项目、同一男主、同一原生母体。必须能表示出发与到达的世界/本地时间、项目事件顺序，是否有时间分支只有作者/已有世界规则确定后才记录。**不得自动要求分支、闭环或恢复原著历史。**
3. **二战开局、三战与后期人物逐渐出现**：原著完整人物、年代、忍术、事件一直保留在 Source Reference；项目实际发生/人物认知/Reader 知识和原著资料分别判断；切入时间仅服务查询当前 Reality，不应删减任何母体世界内容。

## 1. 原版 NarraLume 已经做了什么（不得反复“重新发明”）

原版 `abligail/narralume` 的《故事设定集》是**写前人工/AI 建立设定 + 写作中调用 + 正文完成后由候选采纳写回**的双向设计，并非正文后提取事实的单向工具。

- 七个原生板块：作者意图、大纲、实体、已确认事实、关系、时间线、伏笔。
- `lorebooks`、`lore_entries` 保存面向人/模型阅读的完整文字设定，并支持关键词触发。
- `canon_entities`、`canon_facts`、`relationship_events`、`timeline_events`、`knowledge_records` 保存世界对象、关系、时序与知识。
- AI 修改不会自行覆盖；候选由作者审核采纳，正文状态也通过原有结算程序写回。
- 现有 `Migration 046` 保存 WorldPack 候选，047/048 是已增加但未完整覆盖七版方法的专项世界切面。
- **现有 `Migration 049`** 已有 `source_corpora`、`source_records`、`source_relations`、`project_source_bindings`，可供同一项目挂多份原作/历史参考，不自动写入 Canon。火影导入器和真实 GitHub Actions 验证已在仓库中，**不要再次创建一份与 049 冲突的 Source Corpus**。

相关源码：`packages/persistence/src/migrations/002-story-kernel.ts`、`044-lorebooks.ts`、`049-shared-source-corpora.ts`、`source-corpus-repository.ts`。

## 3. 第二模块的数据库语义（不以表数为完成标准）

- **Source Corpus** 是原著/历史等原生资料，可包含来源冲突；来源记录只是来源声明。原生母体的 Reader 已知价格可以被识别，但不是实际项目获得的权益。
- **Project Canon/Reality** 记录一本小说真正成立的事实，世界数量和旅行次数不影响 Project 身份。
- **同一人物的源身份与项目身份要能够对应**，但不应无证据地把同名者认定为同一人；同一人物跨世界前后项目 ID 不变，只有实际同时存在且不同的实例需要额外区分。
- **时空坐标**是项目内地点、世界区、本地时间、可能的历史分支；**故事事件顺序**是男主已经经历的顺序。两者不必单调相同。
- **时间切片查询**只决定在某个时点发生了什么、当前谁有怎样的权限，不阻止查询完整原著资料，也不自动泄漏信息给角色。
- **同一事件多视图**：政治立场、组织关系、资产、社会评价、消息传播可引用同一个历史事件，不能复制不同版本的独立真相。
- **价值独立性**：长辈、美女、绝世强者、产业、权力与世界原本就可能很有价值，既不是奖励清单，也不是“目前无法获得所以暂不收录”。
- **历史、原著与项目的不同真值空间**：原著记载、推断/传闻、作者创作设定、项目实际发生、Reader 认知不能用一个布尔 `isCanon` 混为一谈。

## 4. 接下来如何验收第二模块

在第一模块暂停的前提下，后续数据库开发以这些行为作为红线：

1. **Source 049 不重复建库**，在已有多母体资料之上做可验证的源对象 ↔ 项目人物/物品/组织 ID 映射，并保留来源和对应置信度。
2. **不增加新 Project**：同一本小说跨世界及楼兰时空旅行仍写同一项目中的事件/角色；世界/时空定位可查，源资料不受项目 Story 变更影响。
3. **可继续进入已有世界内容**：同一宇智波人物关系、力量、家族史，在项目中发生新事实以后可保留历史并按明确时点查询，其他项目不受影响。
4. **原生故事设定集可继续使用**：不重写 Canon、Lorebook、Outline 的职责，也不把 047/048/049 的新表当成脱离作者写作的平行数据库。
5. **逐版对照**：用 `docs/mmorpg/08-world-database-v01-v07-crosswalk.md` 的缺口表持续推进专项世界数据，避免为了显得“完整”而擅自裁掉 v0.1～v0.7 的原文需求。
6. **先解决能运行的垂直链路**，再逐步深化能力、产业、人物生态等专项结构，不因易做的数表取得进度就宣布数据库整体完成。

**如果出现“按开书时间删除世界”“从火影跳海贼变两个项目”“穿越自动强制建分支”“原著只需原地记录男主见过的东西”等提议，先按照本文件逐项纠错，不要继续写代码。**
