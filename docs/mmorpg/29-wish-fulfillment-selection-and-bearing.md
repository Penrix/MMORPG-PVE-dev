# 29｜第一模块选材宪法：男频意淫价值 × 意淫承重

> **STATUS: CURRENT AUTHORITY / MODULE 1 SELECTION POLICY / 2026-11-25**
>
> World Builder 已经知道“世界怎样做完整”，但此前没有足够明确地知道“面对一个已有世界，什么值得优先做厚”。
>
> **第一模块先按男频意淫价值选择高价锚点，再用既有世界框架为它承重；十个 World Family 负责检查选中区域缺什么，不负责平均决定下一张卡写谁。**

## 1. “意淫”在第一模块中的工程含义

这里的“意淫”不是狭义情色。

它指：

> **目标男性 Reader 借男主这个【我】，对“我想成为、拥有、进入、征服、享受、改变、被认可”的可欲人生进行投射。**

第一模块优先寻找高价人物、高价力量、高价身份、高价财富、高价圈层、高价信息、高价空间、高价关系、高价事业，以及真实作品继续验证出的自由、长生、荣耀、收藏、报复、探索、文明改造等方向。

这些不是固定 Schema，只是寻找“什么值得男主碰”的高频搜索方向。

## 2. 八个高频意淫展开轴

| Axis | 第一问 |
| --- | --- |

| circle | 我想和什么人坐到一张桌上？ |
| information | 我想知道别人不知道什么？ |
| space | 我想活进怎样更昂贵的世界？ |
| relationship | 我想和谁形成怎样只有我有的位置？ |
| career | 我想在世界上留下怎样属于我的事业？ |

这些只帮助搜索，不要求每个对象八项填满，也不禁止新轴出现。

## 3. 高价对象的正确定义

### 高价人物

不是简单等于战斗力最高、官位最高、历史最有名或原著戏份最多。

> **高价人物 = 能与男主形成高意淫价值关系，并继续打开更贵人生的人物。**

他/她可以成为老师、贵人、引路人、高位认可者、强敌、部下、盟友、兄弟、高价女人、组织/资源/秘密/地图入口等。

### 高价力量

不是简单等于伤害最高。

> **高价力量 = 如果【我】真正拥有它，会扩大我能做什么、世界怎样看我、我能进入什么、还能继续打开什么未来。**

价格可以来自强度、稀缺、独占、Reader认知、表演、师承、身份重估、圈层入口、开发空间和与高价世界对象的化学反应。

### 低价对象

低价背景不是禁止存在。它可以留在 Source / Evidence；只有在承重、入口、关系、组织运行或 Current Reality 中升价时，才获得昂贵精编配额。

**不因为“世界里确实存在”就获得平权生产权。**

## 3.5 意淫展开不是单选｜一个高价对象可以反复支付剧情

第一模块选择高价对象时，禁止把“怎么意淫”理解成单一最终关系：

~~~text
纲手
→ 老师 / 盟友 / 女人 / 合作者
→ 四选一
~~~

正确理解是：**同一个高价对象可以同时承载多条逐步升价的 Wish-Fulfillment Thread，这整束展开本身就是长期剧情资源。**

例如同一个纲手可以同时存在：

~~~text
注意我
→ 认可我的天赋
→ 亲自教我
→ 主动找我合作
→ 需要我的能力
→ 向我开放别人没有的私人准入
→ 公开替我背书
→ 成为政治盟友
→ 对我形成偏爱
→ 因我而改变原本命运
~~~

这些不是互斥候选，也不是必须一章全部兑现。它们是可以在 Story Time 中分别进入、前景化、回返、叠加和复利的关系声部。

因此第一模块判断“高价人物 / 高价对象”时，还要看：

> **它是否能够持续产生多轮高价意淫展开，而不是只支付一次功能？**

同一对象连接的力量、圈层、身份、秘密、私人准入、公共定价、命运改写越丰富，越可能成为高杠杆世界锚点。

当前代码用共享 `WishFulfillmentFrame.threads[]` 表达这一点。一个对象允许同时被多条 thread 引用；禁止退回单一 `desiredRelation` / `desiredState`。

## 4. 意淫承重：反平衡税原则

> **意淫承重 = 为了让幻想真正值钱，需要哪些 Reality、人、关系、历史、规则、价格、门槛、稀缺、竞争、资格和取得路径把它托起来。**

根规则：

> **承重的目标函数是提高幻想价格，不是降低幻想收益。**

承重可以是高价人物的真实选择权、顶级能力的知识和传承、权位的真实权限、财富的资产权属、圈层的准入、秘密的知情与保密结构、IP/历史对象的预装价格，以及取得以后世界对男主的重新定价。

承重不等于：

- 因为能力太强自动加冷却、反噬、寿命税；
- 因为关系太爽自动制造长期情感债；
- 因为男主赢太多自动安排无关净亏损；
- 为了所谓公平给已得资产安装对称负收益。

真实限制可以存在，但 Authority 必须来自 Source / Current Reality / 人物选择或明确产品增益，不能只来自“太爽所以要平衡”。

## 5. Selection 与既有世界框架分权

既有世界框架继续成立：

~~~text
world-map
factions
npc-ecology
power-system
resources
event-ecology
progression
living-world
social-world
endgame
~~~

Selection Policy 回答：

> **为什么先做这个对象？**

世界框架回答：

> **选中以后，它怎样在世界里真正成立？**

正确顺序：

~~~text
意淫价值选择
→ 高价锚点
→ World Builder Framework
→ 人物 / 组织 / 地点 / 规则 / 资源 / 事件 / 入口 / 价格
→ Atlas Audit
~~~

不是：

~~~text
哪个 Family 数量少
→ 机械补哪个
→ 世界目录越来越全
~~~

---

## 6. Selection 与 Atlas Audit 的硬边界

Selection 决定值得花生产成本的锚点。

Atlas Audit 只检查选中区域是否缺人物连接、组织、地点、权属、力量规则、当前事务、社会价格、入口和取得路径。

因此代码里的 Family 顺序只能解释为：

> **Coverage Audit Order**

不得解释成：

> **Creative Selection Priority**

---

## 7. 双生产目标共用同一个 Selection Policy

### Source World Production

从 Existing IP / 历史 / 原始资料中优先制作可被多本男频复用的高意淫价值世界对象，并补齐承重。原始 Evidence 可以很大，但昂贵 LLM 精编不平权分配。

### Project Reality Expansion

在本书 Current Reality 中，优先补当前男主人生正在逼近、需要或已经升价的世界对象。不能为了百科完整无限补男主当前用不到的资料。

---

## 8. 同人 / 类同人的直接含义

同人 IP 优先名角色、名能力、名组织、名资源、名事件、高价地点与可改变命运的关键关系。

历史 / 时代类同人不是人口普查。优先才子佳人、王侯将相、名臣名将、权贵实权、大商人、行业巨头、目标产品真实高价女性、军权、科举、产业、土地、贸易、技术、作品与时代窗口。

普通对象只有在承重、入口、关系、组织运行或 Current Reality 中升价时进入精编。

## 12. 三模块共享纵轴

本文件虽然是 Module 1 Selection Policy，但【意淫】不是第一模块私有字段。当前代码已建立共享 `WishFulfillmentFrame`，纵向贯穿：

~~~text
Reader意淫什么？
        ↓
这个具体男主自己想要什么？
        ↓
围绕高价对象怎样展开多条意淫线程？
        ↓
什么 Reality 把每条线程托贵？
        ↓
男主怎样通过 Story 真正实现？
        ↓
兑现以后留下什么真实资产？
        ↓
资产继续打开更贵意淫
~~~

权限分工：

- Module 1：SELECT 高价锚点，并补 Fantasy Bearing；
- Module 2：提供 Source / Reader Semantics / Project Reality 等可引用证据，不把“意淫价值”伪装成世界客观属性；
- Module 3：推进具体 thread，引用 bearing evidence，Story 兑现并 settlement；
- Character Agent：不得读取 Reader fantasy / 最终 payoff，只按人物自己的可见 Reality 演。

## 12.1 2026-11-26｜代码已经落地的三模块接口

### Module 1｜意淫展开不是一次性 Selection

当前 `world-production-runner` 已把 Wish-Fulfillment 从“第一步 Prompt 提醒”升级为持续运行队列：

~~~text
未服务的 Wish Thread
        +
未服务的 Bearing Requirement
        ↓
优先生成本轮 WorldWorkOrder
        ↓
完成后记录：
wishFulfillmentThreadIds
bearingRequirementIds
        ↓
下一轮继续检查尚未服务的线程
        ↓
全部服务后
才回退普通 Atlas Coverage Audit
~~~

因此同一个高价对象的：

~~~text
认可
师承
需要
私人准入
公开背书
政治联盟
偏爱
命运改写
……
~~~

不会再因为第一条已经做过就被当成“这个对象已经完成”。

### Module 2｜不新增“意淫数据库”，只提供可引用 Reality surfaces

当前 `WorldAtlasStoryContextBuilder` 已经能同时提供：

- Project Reality confirmed surfaces；
- Source identity / relationship reference surfaces；
- Reader Semantics reference surfaces；
- 完整 Source Card 仅留 Author reference detail，不自动注入 Current Reality。

`StoryObjectField` 把这些 surface 转成稳定 `surfaceRef`。

因此：

> **Module 2 的职责是提供承重证据，不负责给对象写一个永久“意淫分数”。**

同一个纲手、职位、技能、组织在不同男主、不同阶段可以产生不同 Wish-Fulfillment 价值；第二模块只负责保存它们真实是谁、有什么关系、什么价格、什么 Authority。

### Module 3｜没有既有 Wish Frame 时，先从 Object Field 自动规划意淫展开

此前 `StoryDirectorPipeline` 在作者没有显式提供、父层也没有继承 `WishFulfillmentFrame` 时，会退回一个确定性 fallback：

~~~text
当前升级收益
+
进入目标圈层
~~~

它虽然不会跑偏到别的 Road，但仍然过于保守：没有真正读取 Module 2 中当前高价人物、能力、Reader Price、关系和入口，也无法自然产生“同一个高价对象的多线程意淫展开”。

当前代码已经把这个 fallback 替换为 `StoryAuthoringService.planWishFulfillment()`：

~~~text
作者显式 Wish Frame
        ↓ 没有
父层 / 前序继承 Wish Frame
        ↓ 没有
当前 StoryObjectField
+ Protagonist Camera
+ Upgrade Ledger
+ Reader Need / Target Emotion
+ bearingEvidenceCandidates
        ↓
Object-grounded Wish Planner
        ↓
具体 WishFulfillmentFrame
        ↓
Expectation / StoryUnit
~~~

Planner 的硬边界：

- `targetRefs` 只能引用当前 `StoryObjectField` 中真实 `object.id`；
- 至少一个高价对象必须承载两条以上不同 Wish Thread，防止重新把关系压成单选题；
- 每条 thread 都必须有 Bearing Requirement；
- 自动规划阶段 thread 只能是 `selected / candidate`；
- bearing 只能是 `candidate / missing`，`evidenceRefs` 必须为空；
- Planner 无权写 `grounded / realizing / realized / retained`；
- 至少一条 selected thread 必须声明未来希望结算的真实收益；
- 不为了凑数量机械枚举八个展开轴，而是围绕当前真实高价对象尽量展开有价格、能持续写 Story 的关系与状态变化。

因此当前第一次自动创作不再是：

> “升级一步，再进一个圈。”

而是先问：

> **眼前这些真实高价人事物，围绕【我】到底还能怎样一层层变得更特殊、更私有、更公开被承认、更能打开未来？**

已有 Author / inherited Wish Frame 时不会重新调用 Planner，避免连续长篇每章重新做梦、浪费模型调用并破坏已形成的意淫曲线。
### Module 3｜每一条承重要求必须单独举证

旧 StoryUnit 曾使用一个扁平：

~~~text
bearingEvidenceRefs[]
~~~

这会产生假承重：

~~~text
证明了“纲手很贵”
→ 顺手把
  私人信任
  政治权限
  偏爱稀缺
  命运改写
全部标成 grounded
~~~

当前新合同已经改为：

~~~text
bearingEvidence: [
  {
    requirementId,
    evidenceRefs[]
  }
]
~~~

每一个尚未 grounded、且属于本轮推进 thread 的 `FantasyBearingRequirement` 都必须有自己的 Module-2 surface evidence。

如果同一 thread 有两个承重要求，只给一个证据：

> **StoryUnit 不能 READY。**

旧 `bearingEvidenceRefs[]` 只保留存档兼容：**只有恰好一个相关未承重 Requirement 时才能自动归属；多 Requirement 时直接判歧义。**

### Module 2 → Module 3｜承重证据不仅要“存在”，还必须证明对的东西

当前 `WorldAtlasStoryContextBuilder` 对每条已有 surface 派生 `bearingKinds`。这是运行时投影，不写回 Source Fact / Project Reality，也不代表某条 Fantasy Bearing 已经自动成立。

例如：

~~~text
Reader Semantics
→ reader_prior

人物当前确认状态
→ reality
→ 若对象本身是 character，也可作为 person 证据

关系 surface
→ relationship

能力 / 规则 surface
→ rule
→ 只有真的写有学习、前置、训练或取得条件时，才额外支持 qualification

Value / Standing
→ price
→ 只有真的有 scarcity 字段时才支持 scarcity
→ 只有真的有 access 字段时才支持 access

Map / Production
→ access
~~~

因此 Module 3 现在有两道门：

1. `evidenceRef` 必须真实存在于当前 `StoryObjectField`；
2. 该 surface 的 `bearingKinds` 必须包含对应 `FantasyBearingRequirement.kind`。

例如：

~~~text
“纲手是 Reader 熟知高价人物”
可以承：
reader_prior

不能自动承：
relationship
access
私人信任
政治权限
~~~

又例如：

~~~text
“医疗忍者当前负责伤员复核”
可以承：
reality
person

不能自动承：
price
~~~

要证明“他的评级真的能改变男主后续任务价格”，必须另有 `price` 类型 surface。

因此当前硬规则是：

> **有证据不等于承重成立；必须是能证明这一类承重的证据。**

如果不存在匹配 `requirement.kind` 的 surface，第三模块不得拿别的高价信息凑数，应返回 `BLOCKED_WORLD_GAP`，把缺失的关系、价格、入口、资格、规则或当前状态送回 Module 1 补世界。

这一层专门防止另一种隐蔽偷懒：

~~~text
有一条“看起来很贵”的证据
→ 把所有承重 Requirement 一起标 grounded
~~~

这和“每个 Requirement 单独举证”共同组成当前反假承重门禁。
### Module 3 Settlement｜意淫兑现不等于资产化

当前纵轴把 `realized` 与 `retained` 明确分开：

~~~text
realizing
→ Story 正在把意淫线程做进 Reality

realized
→ 本章 Grounded Settlement 已经确认目标结果确实发生

retained
→ Grounded Settlement 还确认了 durable Canon / relationship 写回，
  且该收益与 handoff 的 retainedGainOpportunity / settlementTarget 对齐
~~~

因此 Story handoff 中的 `retainedGainOpportunity` 只是**计划收益**，不再拥有自动入账权。

当前 Settlement 会从已经接受的 Grounded Settlement 中分出两类 claims：

- `confirmedRealityClaims`：summary / state delta / fact / timeline / relationship 等实际发生证据，用于判断 thread 是否至少 `realized`；
- `confirmedRetainedClaims`：真正会形成持久 Canon fact / relationship 的变化，用于判断收益是否能进入 `retainedAssets`。

根规则：

> **计划里的 payoff 不是 Reality；发生过也不等于已经成为可复用资产。**

如果 handoff 说“本章拿到新的任务资格”，但 Grounded Settlement 实际只确认“男主醒来”，则：

~~~text
Wish Thread 继续 realizing
retainedAssets 不增加“新的任务资格”
~~~

如果实际结果已经发生但还没有 durable write-back，则：

~~~text
Wish Thread → realized
但不进入 retainedAssets
~~~

只有真实结果与持久写回都成立时：

~~~text
Wish Thread → retained
收益进入 retainedAssets
成为下一轮更贵意淫的本金
~~~

这就是【赢麻了】在代码里的平仓纪律：**不能把计划收益、场面爽感或未实现势能冒充已实现权益。**
### Author / Director 与 Character POV 继续严格分权

Wish-Fulfillment Frame、Reader Fantasy、Bearing Plan 属于 Author / Director Side。

Character Observation 不包含：

~~~text
readerFantasy
wishFulfillment
bearingEvidence
最终 payoff
~~~

角色只拿：

~~~text
自己知道什么
自己想什么
当前压力
可见 Reality
已有关系
自己的利益与下注
~~~

因此作者可以主动设计“纲手最终偏爱男主 / 公开背书 / 改变命运”，但演员纲手不会被提前告知：

> “Reader 想看你偏爱他。”

她只会在 Director 已定商业故事方向内，依据自身人物条件与当前 Reality 演出具体行动。
